# DroneLab Physics Packages — 0.3.3

Параметризованный движок мультироторных дронов для Unity. Ветка **`physics-packages`** предназначена для разработки, проверки и выпуска двух UPM-плагинов. Здесь развивается физика и её инструменты; карты, интерфейс приложения и сторонние модели могут жить в других проектах.

Дрон задаётся JSON-профилем: масса, центр масс, инерция, расположение роторов, характеристики винтов, сопротивление воздуха, питание и дополнительные эффекты. Среда задаётся отдельным JSON. Математическое ядро вычисляет силы, моменты и состояния привода, а Unity Rigidbody интегрирует движение и обрабатывает столкновения.

**Пакеты 0.3.3 · JSON-контракт 1.0.0 · CSV 1.4.0 · Unity 6000.3 · Python 3.10+ для инструментов · .NET 8 для тестов ядра.** Разработческий проект использует Unity **6000.3.25f1 / HDRP**. Сами плагины не требуют HDRP и сторонних моделей.

## Плагины и архитектура

| Пакет | Назначение | Зависимости |
|---|---|---|
| `com.dronelab.physics` | Pure C# физика, адаптер Rigidbody, JSON-валидация, authoring/import, среда, питание, CSV, диагностика и EditMode-тесты | Newtonsoft JSON и стандартные модули Unity; без Input System |
| `com.dronelab.demo` | Пульт Angle/Acro/Alt Hold, клавиатура/геймпад, камера, HUD, создание стендов и PlayMode-тесты | Physics той же версии и Input System 1.20.0 |

Физика поддерживает произвольное число роторов и их оси. Штатный Demo-контроллер и QuadAllocator поддерживают **четыре параллельных ротора +Y** с управляемыми моментами. Для гексакоптера нужен отдельный allocator/controller. Аэродинамика крыла и полноценный самолётный режим отсутствуют.

Управление задаёт команды моторов, привод рассчитывает RPM и доступное питание, физика учитывает местный поток у роторов/корпуса, передаёт силы/моменты в Rigidbody и фиксирует заряд, температуры, энергию и телеметрию. Это связанные параметрические модели, а не CFD-решатель.

## Вся реализованная физика

Дополнительные эффекты **включаются профилем**. Наличие модели в SDK не означает, что она включена у каждого тестового дрона.

| Блок | Реализация | Физический смысл и границы |
|---|---|---|
| Твёрдое тело | Масса, COM, гравитация, силы, моменты, Rigidbody/PhysX | Ускорение и вращение; коллизии определяются назначенными colliders |
| Инерция | AutoBox, ManualPrincipal, импорт полного симметричного CAD-тензора | Сопротивление изменению вращения; AutoBox — оценка однородной коробки |
| Роторы | Положение, ось тяги, CW/CCW, реактивный момент и плечо силы | Разная тяга роторов создаёт roll/pitch/yaw |
| Винт | OmegaSquared, CtCq, RpmTable, PerformanceMap по RPM/J | Тяга и момент из коэффициентов/таблиц; размеры не восстанавливают неизвестную кривую |
| Отклик двигателя | FirstOrder с отдельными временами раскрутки/замедления | Плавное изменение RPM; простой режим не учитывает энергию вращения |
| Инерционный привод | RotorInertia, энергия вращения, выбег и реакция разгона | Часть момента расходуется на изменение RPM; требуется совместимая электрическая модель |
| Гироскопические эффекты | Момент от углового импульса роторов | Дополнительный момент на корпус при изменении направления осей |
| Корпус в воздухе | AxisApproximation, ProjectedArea, Surfaces | Сопротивление растёт с квадратом скорости относительно воздуха; модели корпуса взаимоисключающие |
| Геометрия сопротивления | Box-проекция, ручной LUT, offline mesh silhouette | Площадь зависит от направления; mesh не определяет Cd и распределение массы |
| Роторное сопротивление | Сила, пропорциональная RPM и боковому потоку | Эмпирический rotor drag в точке ротора |
| Земля | Ограниченный ground effect, отдельный probe каждого ротора | Приближённое усиление положительной тяги около поверхности |
| Поток на роторах | Ограниченные axial correction, translational lift, blade flapping | Эмпирические поправки тяги и hub-момента; не BEMT/dynamic inflow/VRS |
| Атмосфера | Constant или сухая стандартная тропосфера | Температура, давление и плотность; StandardAtmosphere: −500…11000 м |
| Ветер | None, Constant, Gust, Turbulence, CustomField, DrydenFrozen | Местный поток в каждой точке; DrydenFrozen — конечнополосная спектральная аппроксимация |
| Батарея | SOC, OCV-кривая, сопротивление, просадка и расход ёмкости | Эквивалентная электрическая модель без электрохимии и старения |
| Двигатель/ESC | Simple или Electrical, Kv/Kt, сопротивление, ток холостого хода и потери | Без FOC, индуктивности и рекуперации |
| Power governor | Ограничение доступных RPM по напряжению, токам, мощности и заряду | Совместный расчёт мотора, винта и батареи; поддержанный режим RPM/J |
| Температуры | Узлы каждого мотора, ESC и батареи, обдув, Rmotor(T), derating | Потери нагревают компоненты; перегрев снижает допустимую нагрузку |
| Отказ привода | Частичная потеря authority или motor fault | Проверка реакции физики; Demo не гарантирует восстановление на трёх моторах |
| Снижение | Axial/lateral speed, оценка hover inflow, operating envelope | Диагностика необычного режима; **силовой модели вихревого кольца нет** |
| Погода | Пресеты температуры/ветра, метаданные дождя/снега/града | Данные для VFX; воздействие воды/льда на аппарат отсутствует |

Полные уравнения, объяснение **каждой формулы** и ограничения находятся в [PHYSICS_REFERENCE](Docs/Physics/PHYSICS_REFERENCE.md). Соглашения и accepted contract — в [SPECIFICATION](Docs/Physics/SPECIFICATION.md).

## Величины и основные формулы

| Величина | Единица | Роль |
|---|---|---|
| Масса `m`, центр масс `COM` | кг, м | Вес и плечи сил |
| Инерция корпуса `I`, инерция ротора `Jr` | кг·м² | Вращение корпуса и разгон винта |
| Скорость аппарата/ветра `v`, `w` | м/с | Поток: `v_air = v_point − w` |
| Тяга `T`, момент `Q` | Н, Н·м | Сила ротора и нагрузка привода |
| `RPM`, угловая скорость `ω` | об/мин, рад/с | `ω = 2π RPM/60`; единицы нельзя смешивать |
| Плотность `ρ`, площадь `A`, коэффициент `Cd` | кг/м³, м², безразмерный | Аэродинамическое сопротивление |
| Напряжение, ток, мощность, энергия | В, А, Вт, Дж | Питание и энергетический баланс |
| Ёмкость, SOC, температура | А·ч, 0…1, К | Заряд, нагрев и ограничения |

| Формула | Простое объяснение |
|---|---|
| `T = kT ω²`, `Q = kQ ω²` | В простом режиме удвоение RPM увеличивает тягу/момент в четыре раза |
| `T = Ct ρ n² D⁴`, `Q = Cq ρ n² D⁵` | CtCq учитывает плотность и диаметр; `n = RPM/60` |
| `τ = r × F` | Сила вдали от центра масс поворачивает дрон |
| `Fdrag = −½ ρ Cd A |v_air| v_air` | Возрастающее сопротивление тормозит движение относительно воздуха |
| `Vbus = Voc − I Rbattery` | Нагрузка вызывает просадку напряжения |
| `SOCnext = SOC − I Δt/(3600 capacityAh)` | Ток расходует заряд |
| `Cth dT/dt = Ploss − G(T − Tambient)` | Компонент нагревается от потерь и охлаждается воздухом |

Векторы профиля: **+X вправо, +Y вверх, +Z вперёд**. Физические координаты уже в метрах; root и родители имеют scale `(1,1,1)`. Масштаб исходной 3D-модели — отдельные метаданные. Подробные единицы всех коэффициентов: [PHYSICAL_QUANTITIES](Docs/Physics/PHYSICAL_QUANTITIES.md).

## Быстрый запуск в Unity

1. Открыть проект в Unity **6000.3.25f1**. Здесь используются исходники из `Assets/DronePhysics`; устанавливать вторую копию плагинов в этот же проект не нужно.
2. Создать сцену с поверхностью/collider и камерой.
3. **DroneLab → Test Bench → Combined Physics Drone**. Назначить дрон целевой камере, сохранить сцену.
4. Play → кликнуть Game View → **F** (arm) → **H** (удержание высоты).
5. WASD — наклон, Q/E — yaw, Space/Ctrl — изменение высоты при H, Z — Angle/Acro, Backspace — reset.
6. Проверить HUD: ветер, сопротивление, RPM, тяга, питание, температуры и ограничения.

**Angle** возвращает аппарат к заданному наклону; **Acro** задаёт угловую скорость и не возвращает горизонт после отпускания кнопок. **H держит только высоту**, не горизонтальную позицию. `throttle 0%` при H показывает ручной ввод, а не нулевую тягу: высотный регулятор сам управляет моторами.

Reference Drones содержат частичные профили Crazyflie 2.0, Crazyflie Brushless и Hummingbird. Неизвестные body drag/power/thermal параметры выключены. Наклонённый reference-дрон без сопротивления способен разгоняться неограниченно: такой профиль не подходит для оценки реальной максимальной скорости и всей траектории. Для совместной проверки используйте Combined Physics Drone; конкретному аппарату нужны откалиброванные параметры.

## Разработка и выпуск

В **0.3.3** источником истины остаётся `Assets/DronePhysics`. `Distribution/Packages` генерируется. Изменения установленного пакета сначала переносите в исходники; таблица соответствия и Windows/Linux-инструкции — [DEVELOPMENT](Docs/Physics/DEVELOPMENT.md).

Из корня репозитория, одинаково в PowerShell и Linux shell:

```console
python Tools/build_unity_packages.py
python Tools/build_unity_packages.py --check
python -m unittest discover -s Tests/Python -v
```

На Linux используйте `python3`, если `python` отсутствует. Математическое ядро:

```console
dotnet test Tests/DotNet/DroneLab.Physics.Tests.csproj --configuration Release
```

Контракт меняется через `Tools/generate_physics_contract.py`: вместе обновляются DTO, обе JSON-схемы и `PARAMETERS.md`. Версия двух пакетов задаётся одной константой `VERSION` сборщика. Коммит включает исходники, документацию, тесты, `.meta` и оба пакета. Из внешних моделей в SDK не включён полноценный сторонний mesh.

В другом проекте Git-установка требует оба пакета с одинаковым SHA; embedded-установка — копирование двух папок из `Distribution/Packages` в `Packages` целевого проекта. Инструкция: [MODULE_INTEGRATION](Docs/Physics/MODULE_INTEGRATION.md).

## Проверки, точность и ограничения

- Регрессии проверяют формулы, знаки, единицы, пределы, reset и энергетический баланс. Приёмка этапа 14: **482 pure C#/EditMode-проверки**; это исторический результат, не новый запуск Unity.
- Независимые стендовые точки Bitcraze/UIUC проверяют характеристики винта. У CF2 средняя ошибка интерполяции тяги 3.313%, максимум 16.153% на малых RPM. Это **не ошибка полного полёта**.
- Для 0.3.3 добавлены проверки Windows-путей, UTF-8/BOM/CRLF, пробелов/кириллицы, метаданных и воспроизводимости. CI запускает инструменты и .NET-тесты на Windows/Ubuntu. Фактический статус — GitHub Actions и [VALIDATION](Docs/Physics/VALIDATION.md).
- Unity PlayMode, импорт пакетов и EXE проверяются отдельно в Unity. Python/.NET-проверки не заменяют этот этап.

CFD/BEMT, динамический индуцированный поток, VRS-силы, взаимодействие следов роторов, деформация/разрушение, электрохимия, датчики/шумы, EKF и прошивочный автопилот не реализованы. Demo использует идеальное состояние Rigidbody. Новые формулы сами по себе не подтверждают точность конкретного аппарата.

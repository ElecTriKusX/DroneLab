# DroneLab Environment 0.2.0

Адаптер Enviro 3 для DroneLab Physics 0.3.4. Выбор погодного профиля, ручной ветер/температура, время суток и живое
состояние воздуха для сил, привода и теплообмена во время Play Mode.
Источник — `Assets/DroneEnvironment`; UPM — `com.dronelab.environment`.
Enviro требуется отдельно: сборщик не включает его исходники или ресурсы.

## Состав и физические величины

| Компонент / величина | Назначение и единицы |
|---|---|
| `WeatherSnapshot` | Неизменяемое состояние после обновления Enviro; отметка времени в секундах Unity |
| `EnviroWeatherController` | `IWindProvider` / `IAirProvider` / `IWeatherProvider`, API управления и диагностическое окно |
| `WindWorldMps` | Скорость движения воздуха в мировых осях, м/с; +X вправо, +Y вверх, +Z вперёд |
| `TemperatureK` | Локальная температура Enviro: `°C + 273.15`; контрольная температура атмосферы |
| `referencePressurePa` | Локальное давление на контрольной высоте, Па; Enviro его не предоставляет |
| `referenceAltitudeM`, `referenceWorldY` | Контрольная высота над уровнем моря и соответствующая мировая Y, м |
| `WeatherState` | Общий снимок ветра, атмосферы и metadata; запросы не меняют состояние |
| `weatherBindings` | Явная привязка Enviro-пресета к виду осадков и интенсивности 0…200 мм/ч |
| `Wetness`, `SnowCover` | Доли 0…1; не интенсивность осадков в мм/ч |
| `VisualTurbulence` | Коэффициент Enviro 0…1; не физическая дисперсия скорости |
| `fullStrengthWindMps` | Явная калибровка: сколько м/с соответствует `windSpeed=1` |
| `northYawDegrees` | Поворот севера сцены по часовой стрелке от +Z, градусы |

Enviro хранит силу ветра в диапазоне 0…1, без единицы м/с. Значение полной шкалы
**20 м/с по умолчанию — настройка адаптера, а не характеристика библиотеки**.
Преобразование: `V = normalize(-windDirectionX, 0, -windDirectionY) × windSpeed × fullStrengthWindMps`.
Знак соответствует `EnviroEnvironmentModule.UpdateWindZone`; поле Y у Enviro обозначает мировую Z.
Нулевой вектор направления означает штиль. Скорость выше выбранной шкалы отклоняется.

Метеорологическое направление указывается **ОТКУДА** дует ветер: 0° — с севера,
90° — с востока. При севере +Z ветер с севера движется вдоль −Z.
Ручное переопределение меняет Environment и WindZone; физика получает тот же вектор.
При плавном переходе между профилями читаются текущие применённые параметры,
а не конечные значения целевого профиля.

## Согласование с физикой

Температура читается после обновления Enviro или задаётся ручным переопределением.
Давление задаётся явно на контрольной высоте. Один снимок управляет ветром и колонкой
сухого воздуха: `deltaH=worldY-referenceWorldY`, `h=referenceAltitudeM+deltaH`,
`T=referenceTemperatureK-0.0065*deltaH`,
`p=referencePressurePa*(T/referenceTemperatureK)^(9.80665/(287.05287*0.0065))`,
`rho=p/(287.05287*T)`. Плотность имеет единицу кг/м³.
Контрольные T=200…330 К, p=1000…200000 Па; высоты −500…11000 м.

Это локальная контрольная точка: 80000 Па на высоте 2000 м не трактуются как давление
на уровне моря. Температура Enviro относится к referenceWorldY; выше дрон получает
температуру и давление колонки. В каждой StepPhysics один AirSample используется
для тяги/момента, drag, силовых ограничений и температуры охлаждающего воздуха.
Изменение погоды не вызывает Initialize/Reset: SOC, энергия, нагрев и обороты сохраняются.
PID Demo использует последнюю применённую плотность; смена источника имеет задержку
до кадра, а компенсация управления может отставать на один физический шаг.

Живой воздух требует **CtCq или PerformanceMap**. Измеренные OmegaSquared/RpmTable
не масштабируются автоматически: подключение такого источника отклоняется до полёта.
Для ветра с измеренным профилем отключить `syncAir` до запуска и назначить только wind provider.
`syncAir` выбирается при подключении; для смены режима требуется перезапуск Play Mode.

## Подключение в разработческом проекте

1. Добавить настроенный prefab Enviro, назначить камеру и включить модули Weather/Environment.
   Time нужен для управления временем суток. Для первой проверки использовать одну глобальную зону.
2. Создать **DroneLab → Test Bench → Combined Physics Drone**. Его профиль включает
   `windInteraction`, сопротивление корпуса, питание и тепловую модель.
3. Выделить объект с `DronePhysicsBody` → **DroneLab → Environment → Connect Selected Drone to Enviro**.
   Сохранить предложенную новую копию JSON среды. Меню назначает `CustomField`, отключает
   gust overlay и связывает wind/air providers с дроном. Новому контроллеру
   назначается контрольная высота из JSON, мировая Y стартового COM и локальное давление.
   Проверить эти настройки перед полётом; давление не является измерением Enviro. Остальные параметры JSON сохраняются.
4. Сохранить сцену, запустить Play. В Game View выбрать профиль или включить Manual wind override.
   При штиле/5 м/с/смене направления сравнить вектор в окне и CSV `wind_x_mps`, `wind_y_mps`, `wind_z_mps` физики.
   Включить ручную температуру и сравнить `density_kgm3` / `ambient_temp_k`
   CSV со строкой Live air; плотность меняется при температуре/давлении. SOC и энергия
   должны продолжать изменяться без сброса. Для повторного подключения выбрать новый JSON.

Подключение выполняется до `DronePhysicsBody.Awake`. Для ручной настройки назначить
`customWindProvider` и `customAirProvider`, `manager`, `droneTargets`, `windMode=CustomField` и `gustEnabled=false`.
При добавлении адаптера к уже инициализированному дрону требуется перезапуск Play Mode.
Одна копия SDK в проекте: исходники Assets либо установленные UPM-пакеты.

## API и порядок исполнения

```csharp
// SelectWeather/SetTimeOfDay вызываются после controller.IsReady == true.
controller.SelectWeather(0);                // плавный переход по настройкам Enviro
controller.SelectWeather(0, instant: true); // моментальный переход
controller.SetManualWind(5, 90);            // 5 м/с с востока
controller.UsePresetWind();                // вернуть ветер погодного профиля
controller.SetManualTemperature(20);         // контрольная температура 20 C
controller.UsePresetTemperature();          // вернуть сезон/время/погодную поправку Enviro
controller.SetAirReference(80000, 2000, 100);// местное давление, высота над морем, мировая Y
controller.SetTimeOfDay(12, simulate: false);
var applied = controller.Current;
```

Привязка выполняется в Awake с порядком −500. Чтение/переопределение — в LateUpdate
после Start и Update Enviro, когда модули уже склонированы для исполнения.
Все FixedUpdate одного кадра используют последний завершённый снимок: задержка до кадра.
`Sample` только читает снимок; не меняет погоду, не выполняет HTTP и не сбрасывает дрон.
До первого снимка ветер — штиль, воздух/осадки — JSON fallback. При отключении или
недопустимых данных сохраняется последний полный валидный снимок; причина видна
в Status/Console. Это остановка обновления среды, а не сброс дрона.
Будущий GUI вызывает тот же API; `showEngineeringWindow=false` скрывает встроенное окно.

Ручной выбор отключает автоматическую смену погоды и восстанавливает её исходное
значение при отключении адаптера. Переход между локальными зонами и другие скрипты
Enviro всё ещё могут заменить профиль. Использовать один управляющий адаптер на Manager.

## Текущие ограничения

Ветер однородный и горизонтальный; атмосфера сухая, без влажности/теплообмена самого
воздуха с поверхностями. Давление задаётся пользователем или будущим провайдером.
Визуальная турбулентность не преобразуется в Dryden или физические порывы.
Дождь/снег/град остаются VisualOnly metadata/VFX, без дополнительных сил, массы или обледенения.

`weatherBindings` связывает конкретный asset Enviro с None/Rain/Snow/Hail и явной
интенсивностью мм/ч. Без привязки metadata=None/0; wetness и particle emission не
превращаются в измеренные осадки. При переходе metadata относится к целевому профилю,
а ветер/температура — к текущим применённым значениям. Привязки не изменяют VFX Enviro.

Ручная температура переопределяет применённое Environment.temperature после Update;
внутренние сезонные кривые и расчёт wetness/snow продолжает выполнять Enviro.
Реальные метеоданные ещё не подключены. Облака/VFX определяются собственными модулями
Enviro; импорт, визуальное соответствие и сохранение состояния Rigidbody требуют Unity.

## Пересборка и проверки

Из корня репозитория, Windows PowerShell или Linux:

```console
python Tools/build_environment_package.py
python Tools/build_environment_package.py --check
python -m unittest discover -s Tests/Python -v
dotnet test Tests/Environment/DroneLab.Environment.Tests.csproj --configuration Release
```

На Linux допускается `python3`. Экспорт использует POSIX-пути, UTF-8/LF,
детерминированные GUID и SHA-256. `.meta` скриптов сохраняются из исходников.
Для другого проекта: сначала установить Enviro и Physics 0.3.4, затем Add package from disk
с `Distribution/Packages/com.dronelab.environment/package.json`.
Для Unity Test Runner добавить `com.dronelab.environment` в массив `testables`
файла **`<корень Unity-проекта>/Packages/manifest.json`**, рядом с `Assets` и `ProjectSettings`.

Чистые C# тесты проверяют оси/знак, метеорологические направления, поворот севера,
обратное преобразование, границы шкалы, штиль, нечисловые значения и единицы температуры.
Дополнительно проверяются общий снимок, идеальный газ, локальная высота/давление,
согласование плотности с тягой/drag, совместимость профилей и сохранение истории питания/тепла.
Они не выполняют Enviro, Rigidbody или Unity Play Mode. `LiveAirRigidbodyTests` подготовлен
для Unity Test Runner; запуск в этом окружении не выполнялся.

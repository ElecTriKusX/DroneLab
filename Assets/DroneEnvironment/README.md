# Источники среды и визуальная погода

Модуль связывает физическую среду DroneLab с погодой и освещением сцены. Ядро остаётся независимым от конкретного визуального провайдера.

Пользовательская настройка находится в [руководстве среды](https://github.com/ElecTriKusX/DroneLab/blob/main/Docs/UI/SCENARIOS_AND_ENVIRONMENT.md); физические уравнения — в [справочнике](https://github.com/ElecTriKusX/DroneLab/blob/main/Docs/Physics/PHYSICS_REFERENCE.md).

## Состав и единицы

| Часть | Назначение |
|---|---|
| `Core` | Согласование воздуха/ветра и чистые расчёты без Unity |
| `Runtime` | Подключение сцены, управление применённым состоянием и снимками |
| `Editor` | Инструменты настройки и интеграции |
| `Profiles` | Сохранённые настройки визуальной среды |

`IWindProvider` предоставляет мировой вектор в м/с, `IAirProvider` — воздух, `IWeatherProvider` — метаданные погоды. Температура передаётся в K, давление в Па, высота в м, плотность в кг/м³.

0° направления ветра означает источник с севера (+Z), 90° — с востока (+X). Скорость в физических расчётах не ограничивается насыщением визуального эффекта. Горизонтальный WindZone может не отображать вертикальную компоненту, которая продолжает действовать на аппарат.

## Согласование с физическим телом

Для внешнего поля назначьте источник до инициализации тела, используйте `CustomField` и включённое `windInteraction`. Для внутреннего профиля физики визуальный драйвер показывает его применённый поток и не заменяет расчёт сил.

Воздух применяется согласованным снимком: аэродинамика, привод и охлаждение используют одно состояние. Внешняя атмосфера требует совместимой CtCq/PerformanceMap-модели. Ω²/RpmTable с измеренными силами не масштабируются по плотности скрыто; для подключения только ветра можно оставить воздух профиля.

При атмосферной колонке задаются местное опорное давление, температура, высота над уровнем моря и мировая Y этой точки. Во время перехода читается текущее применённое состояние, а не только конечные значения целевого пресета.

## Подключение сцены

1. Настройте один управляющий погодный адаптер и его связи со сценой.
2. Назначьте целевые аппараты и необходимые источники ветра/воздуха.
3. Проверьте камеру, освещение, необходимые визуальные модули и стартовую атмосферу.
4. Проверьте в Play Mode, что показания F3 и физическая телеметрия согласованы.

Запросы физических интерфейсов читают завершённый снимок. Обновление визуального провайдера может запаздывать до кадра; нельзя выполнять сеть, смену профиля или сброс дрона внутри `Sample`.

Ручное переопределение ветра возвращается к исходному источнику после выключения. Ручные функции адаптера температуры/времени предназначены для интеграции; полный UI полёта предоставляет редактирование ветра, остальные погодные показания там читаются.

## Границы и проверка

Осадки, облака, мокрота и снег поверхности — визуальные данные. Водяная масса, влажность газа, обледенение и повреждения не рассчитываются. Реальный метеосервис не подключён.

Источник не должен конкурировать со вторым драйвером того же состояния. Проверяйте отсутствие второго набора сил на Rigidbody, корректность локальной опоры воздуха и знака ветра.

Экспорт модуля выполняет `Tools/build_environment_package.py`; изменения этого README также требуют пересборки. Проверки и команды находятся в [TESTING.md](https://github.com/ElecTriKusX/DroneLab/blob/main/Docs/TESTING.md).

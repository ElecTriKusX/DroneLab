# Первый запуск на Terrain

## Получить код

```bash
git fetch origin
git switch codex/physics-foundation
git pull --ff-only
```

Открыть проект в Unity **6000.3.25f1**, дождаться разрешения пакетов и компиляции.
Добавлен официальный `com.unity.nuget.newtonsoft-json` 3.2.1.
Новый Input System уже есть в проекте. Тесты используют установленный Unity Test Framework.

## Создать стенд

1. Открыть свою новую сцену с Terrain, освещением и Main Camera.
2. Убедиться, что Terrain имеет TerrainCollider.
3. В **Edit → Project Settings → Time** установить **Fixed Timestep = 0.01**.
4. Выбрать Terrain или объект около нужной точки старта.
5. Нажать **DroneLab → Create Physics Test Drone**.
6. Получится `DroneLab TestQuad`: Rigidbody, BoxCollider, DronePhysicsBody, DroneTestPilot
   и дочерний визуальный куб. Роторы — данные JSON; четыре отдельных GameObject не нужны.
7. Для камеры добавить на Main Camera **DroneTestCamera**, перетащить корень дрона в `Target`.
8. Сохранить сцену. Нажать Play, кликнуть Game View, нажать **F** для запуска моторов.

Первый старт — с выключенным Altitude Hold. Нажать **H** для проверки удержания высоты.
Без H и без пробела дрон падает. Неактивированный дрон тоже падает — это ожидаемо.
Стабилизация направления и высоты работает через команды четырём моторам.

## Подставить красивую модель

Удалить только дочерний `Visual - replace with your asset`; поместить модель дочерним
объектом корня. Подогнать её local position/rotation/scale так, чтобы нос смотрел по
локальному +Z корня, верх по +Y. Корень и его родители: scale (1,1,1).
Не добавлять второй Rigidbody в модели. Использовать корневой BoxCollider или составные
примитивные Collider; non-convex MeshCollider на динамическом Rigidbody не подходит.

Для первой проверки визуальная модель не изменяет физику: профиль остаётся синтетическим
TestQuad 1 kg. Реальные размеры/расположение роторов и характеристики позже задаются в JSON.
Старые экспериментальные моторы, drag и WindReceiver не должны действовать на этот корень.

## Управление

| Клавиша | Действие |
|---|---|
| F | Arm / Disarm |
| W / S | Наклон вперёд / назад; в Acro — соответствующая угловая скорость |
| A / D | Наклон влево / вправо |
| Q / E | Поворот налево / направо |
| Space | В ручном режиме заданная тяга; при удержании высоты — повышает целевую высоту |
| Ctrl | В ручном режиме нулевая команда; при удержании высоты — снижает целевую высоту |
| Z | Angle (выравнивание) / Acro (стабилизация угловой скорости) |
| H | Включить / выключить удержание высоты |
| Backspace | Вернуть стартовую позу и обнулить моторы, disarm |

После отпускания пробела моторы получают target RPM=0, если высота не удерживается.
Фактические обороты затухают по τ, а не мгновенно. Тестовый Space даёт 38% максимальной
суммарной тяги; профиль имеет T/W=4. Доступен gamepad: Input Device = Gamepad, RT/R2 задаёт ручную тягу 0–100%.
Подробности PID, геймпада и проверки этапа 2: [FLIGHT_CONTROL.md](FLIGHT_CONTROL.md).
При Altitude Hold аппарат удерживает высоту, но **не позицию X/Z**: ветер будет его сносить.
При потере фокуса приложение делает disarm. Game View должен получать ввод.

## JSON и ветер

Файлы в `Assets/DronePhysics/Resources/DronePhysics/`:

- `quad_test_basic.json`: 1 kg, 4 ротора, max 10000 RPM, hover 5000 RPM.
- `quad_test_ctcq.json`: тот же синтетический аппарат в модели постоянных Ct/Cq.
- `environment_calm.json`: без ветра.
- `environment_wind.json`: ветер +X 5 m/s.
- `drone-profile.schema.json`, `environment-profile.schema.json`: контракт.

Назначить нужные TextAsset в DronePhysicsBody до Play. Пустые ссылки используют Basic/Calm.
Изменения JSON читаются при запуске/Initialize, не автоматически каждый кадр.
Чтобы проверить ветер, выбрать Wind и включить H. Дрон должен дрейфовать по +X.
Gizmos: зелёные силы роторов, красное сопротивление, синий ветер, жёлтый COM.
В Game View включить Gizmos, если стрелки нужны там.

## Проверка этапа

В **Window → General → Test Runner** выполнить EditMode, затем PlayMode тесты.
PlayMode тесты создают свой объект высоко над землёй, чтобы Terrain не мешал проверке.
Нужна спокойная сцена без других скриптов, меняющих глобальные настройки или генерирующих ошибки.

Ожидается:

1. Console без ошибок загрузки/компиляции; предупреждения о синтетических данных нормальны.
2. RPM и тяги отображаются; равные 5000 RPM дают 9.81 N суммарно.
3. F + H удерживает высоту после переходного процесса; не обещает удержание позиции.
4. W наклоняет нос вперёд, D вправо; Q/E поворачивают в обе стороны.
5. Выключить H, отпустить пробел: обороты снижаются до нуля, аппарат падает.
6. Wind сносит по +X; Backspace возвращает старт; Z отключает автоматическое выравнивание.

Если есть проблема, прислать первую ошибку Console, скрин Inspector корня и короткое
описание режима (Angle/Acro, H, ветер). Не менять kT/kQ наугад для исправления знаков управления.

Для проверки ядра без Unity:

```bash
dotnet test Tests/DotNet/DroneLab.Physics.Tests.csproj
```

Результаты текущей проверки и её ограничения записаны в `VALIDATION.md`.

Метровые ориентиры и проверка отклика: [BEHAVIOR_BASELINE.md](BEHAVIOR_BASELINE.md).
После выделения дрона можно выполнить **DroneLab → Create Scale References (meters)**.

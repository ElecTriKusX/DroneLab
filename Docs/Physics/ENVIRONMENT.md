# Этап 7: атмосфера и ветер

JSON-контракт остаётся **1.0.0**: реализованы ранее зарезервированные настройки
EnvironmentProfile. Геометрия по-прежнему запекается в редакторе. В каждом физическом
шаге вычисляются плотность и аналитический ветер, затем силы; mesh не пересчитывается.

## Первая проверка на своей сцене

Для начала используй батарею с достаточным запасом заряда и тока. Ограничение 4 A
или очень маленькая батарея затрудняют наблюдение ветра: моторы уже ограничены питанием.
Текущий профиль дрона, его геометрию и измеренные характеристики менять не требуется.

1. Выйди из Play и выдели **корень дрона с DronePhysicsBody**.
2. В верхнем меню нажми **DroneLab → Environment → Create Environment Profile**.
3. Проверь **Drone root**. Выбери **Wind mode = Gust**.
4. **Mean wind world m/s = (5, 0, 0)**, **Fluctuation bound m/s = 2**,
   **Time scale / gust period s = 2**. **Variable atmosphere** оставь выключенным.
5. Нажми **Validate and save new environment JSON**, сохрани, например,
   `Assets/environment_gust_test.json`. Профиль автоматически назначается дрону.
6. Сохрани сцену, запусти Play, кликни Game View, нажми **F**, затем **H**.
7. В HUD появятся **Environment**, **density**, **Wind**, **simulation**.
   X-компонента ветра циклически изменяется **5 → 7 → 5 m/s** за две секунды.
   Дрон сносит по +X; H удерживает только высоту.

Если ветер не действует, проверь в JSON дрона
`physicsConfiguration.modules.windInteraction`: должно быть **true**.

## Турбулентность и повтор

В том же окне выбери **Turbulence**, оставь средний ветер (5,0,0), амплитуду 2 m/s,
временной масштаб 2 s, **Turbulence seed = 48271**. **Periodic gust overlay** выключи.
Сохрани новый JSON и сцену. Ветер плавно меняется по трём осям и зависит от положения.
**Backspace** возвращает дрон на старт и обнуляет часы среды. При одинаковом seed,
стартовой позе и командах получается повторяемый сценарий. Одинаковый seed сам по себе
не обещает одинаковый ветер на разных координатах.

## Пространственный CustomField

1. Создай отдельный неподвижный GameObject, например `Wind Field`.
2. **Add Component → Drone Wind Field**.
3. Задай **Mean Wind World Mps = (5,0,0)**,
   **Gradient Y = (0.1,0,0)**, **Maximum Delta Mps = 10**.
4. В окне Environment выбери **CustomField** и перетащи компонент в
   **IWindProvider component**. Сохрани новый environment JSON и сцену.

Не делай поле дочерним объектом дрона: его позиция — неподвижная точка отсчёта.
Здесь каждые 10 m подъёма относительно объекта поля добавляют 1 m/s к ветру по X,
пока добавка не достигнет ограничения. Gradient X/Y/Z — изменение **вектора ветра**
на метр по соответствующей мировой оси. Поворот GameObject не вращает эти оси.
Ветер берётся отдельно в COM, в каждой точке ротора и в CP/каждой поверхности корпуса.
Поэтому пространственный градиент может создавать момент даже без вращения дрона.

## Переменная атмосфера

Это отдельная проверка: измеренные **OmegaSquared kT/kQ и RpmTable нельзя автоматически
масштабировать**. Для Variable atmosphere все роторы должны использовать **CtCq**
или **PerformanceMap**. Если текущий профиль использует измеренные таблицы,
продолжай проверять ветер с постоянной плотностью. Для атмосферного теста можно создать
отдельный TestQuad и назначить `Resources/DronePhysics/quad_test_ctcq.json`.

В окне включи **Variable atmosphere**, выбери **Wind mode = None**,
**Start altitude MSL m = 3000**. Сохрани новый JSON. На старте плотность будет около
**0.9091 kg/m³**, вместо около **1.2250 kg/m³** у уровня моря. При одинаковых RPM
тяга и Q ниже; H запрашивает больше оборотов для поддержания веса. Пульт компенсирует
плотность в allocator, однако ограничения батареи и моторов могут помешать висению.
Установка MSL не перемещает Terrain или дрон на 3000 Unity units.

`altitudeM` — высота COM над уровнем моря **при Initialize**.
Далее `h = altitudeM + (worldCOM.y − initialWorldCOM.y)`. Один Unity unit — один метр.
Плотность вычисляется в COM и используется для всего аппарата в данном шаге.
Пульт использует последний снимок воздуха; обновление происходит в следующем physics step.

## Формулы и значения параметров

| Поле | Реализованный смысл |
|---|---|
| airDensityMode = Constant | Используется airDensityKgM3; T/P — только метаданные |
| airDensityMode = StandardAtmosphere | Сухая тропосфера: T = T0 − 0.0065 h; P = P0 (T/T0)^(9.80665/(287.05287 × 0.0065)); ρ = P/(287.05287 T) |
| temperatureK / pressurePa | В StandardAtmosphere — опорные значения T0/P0 у уровня моря; при отсутствии 288.15 K / 101325 Pa |
| altitudeM | Начальная высота COM, m; при отсутствии 0 |
| windVelocityWorldMps | Средний ветер в мировых осях, m/s |
| gustEnabled | Периодическая добавка вдоль среднего ветра; при нулевом среднем направлении +X |
| gustIntensityMps | Верхняя граница нормы добавки, не RMS и не стандартное отклонение |
| gustTimeScaleS | Период порыва; для турбулентности масштаб длины L = max(1 m/s, |mean wind|) × time scale |
| turbulenceSeed | Seed собственного xorshift32; обязателен для Turbulence |

StandardAtmosphere ограничена **−500…11000 m**, T0=200…330 K, P0=1000…200000 Pa.
`airDensityKgM3` остаётся обязательным полем контракта; при StandardAtmosphere runtime
вычисляет плотность и не использует это поле как источник. Выход за диапазон останавливает
модуль с ошибкой. Стандартная гравитация 9.80665 в формуле давления не заменяет
`gravityMps2` для движения Rigidbody.

Порыв: `ΔW = direction × 0.5 I (1 − cos(2π t/τ))`.
Wind mode Gust требует gustEnabled=true. Constant и Turbulence могут включать такой
порыв дополнительно; None и CustomField его не используют.

Турбулентность: восемь аналитических поперечных синусоид
`W(p,t) = Wmean + Σ ai sin(ki · (p − U t) + φi)`.
Направления, фазы и длины волн определяются seed; `ai ⟂ ki`, `|ai| = I/8`, поэтому
`|W−Wmean| ≤ I` без порыва. Поле переносится средним ветром; при его скорости <1 m/s
используется перенос (1,0,0) m/s. При включённом дополнительном порыве общий предел — 2I.
Нет пошагового random state: результат зависит от координат, времени и seed,
не от количества/порядка запросов. dt меняет интегрирование движения, но не само поле.
Часы каждого дрона начинаются с нуля при Initialize/ResetMotorState.

Это **воспроизводимое ограниченное тестовое поле**, не Dryden, не Kolmogorov spectrum,
не метеорологические измерения и не CFD. Нет расчёта обтекания Terrain, следа винтов,
экранирования препятствиями, влажности или VFX. Для таких задач нужен другой провайдер
и отдельная проверка его модели.

## Связь с остальной физикой

Ct/Cq тяга и Q получают текущую плотность **один раз**. PowerSystem считает Qω с той
же плотностью; плотность влияет и на доступные RPM через энергетику. Корпус получает
текущую плотность и относительную скорость в каждой точке. Ground effect остаётся
отдельным множителем T; эмпирический rotor drag Krd не получает выдуманный множитель ρ.
Пульт сохраняет статическую J=0 модель allocator: переменный осевой поток карт этим
этапом не компенсируется. Battery + PerformanceMap всё ещё явно отклоняется.

`IWindProvider.Sample(worldPositionM, timeS)` возвращает DVector3 в m/s, должен быть
без побочных эффектов и не зависеть от порядка запросов. Компонент назначается через
DronePhysicsBody.customWindProvider, программный объект — через CustomWindProvider.
Провайдер обязателен только для включённого CustomField. `windInteraction=false`
отключает влияние всех режимов. Неконечные результаты и компоненты >10⁶ m/s отклоняются.
Все запросы ветра и сил проверяются до AddForce и расхода заряда данного шага.

## Проверка

Запусти **Window → General → Test Runner → EditMode → Run All**, затем **PlayMode → Run All**.
В PlayMode добавлены 12 EnvironmentRigidbodyTests в изолированных physics scenes:
порыв, повтор seed, ветер роторов/CP/patches, ISA, согласованность батареи с Q,
отключение ветра, reset, некорректный/отсутствующий provider и H в разреженном воздухе.
В ядре проверены также границы поля, идеальный газ, однократное density scaling,
dt convergence и altitude PID на 50/100/200 Hz. Фактические результаты — VALIDATION.md.

Справочные первичные источники:
[MathWorks atmosisa](https://www.mathworks.com/help/aerotbx/ug/atmosisa.html)
для ISA и высоты;
[NASA: Earth atmosphere, metric](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/earth-atmosphere-equation-metric/)
для связи высоты, давления, температуры и плотности (у NASA округлённые коэффициенты);
[MathWorks Dryden](https://www.mathworks.com/help/aeroblks/drydenwindturbulencemodeldiscrete.html)
для отличия спектральной модели Dryden от реализованного демонстрационного поля.
Высота Unity здесь используется как приближение геопотенциальной высоты; верхние слои ISA
не реализованы.


## Этап 12: thermal ambient и weather API

Для enabled thermal нужен действительный ambient T: Constant требует явного
temperatureK 100..500 K, StandardAtmosphere выдаёт local altitude temperature.
Охлаждение использует actual point airspeed; environment reference temperature для
тропосферы остаётся sea-level. Weather presets warm/snow/rain/hail и optional
weather={precipitation,intensityMmPerHour,model:VisualOnly} доступны UI/VFX через
RuntimeEnvironment. Осадки сами не меняют силы, плотность, humidity или нагрев;
описание границ и интеграции — THERMAL_WEATHER.md.

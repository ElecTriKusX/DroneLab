# Карты и профили среды

Рабочая реализация вкладки «Сценарии и окружение» в главном меню. Два независимых раздела: галерея карт и библиотека профилей. Карта не содержит ссылки на профиль среды. В заголовке ДРОНЛАБ нет иконки. Графит, тонкие обводки, левое выравнивание, компактные списки, собственный графитовый scrollbar; вся страница масштабируется вместе с меню от 1920×1080.

## Карты и скриншоты

Откройте MainMenu, выберите **DroneLab Main Menu → DroneScenarioController**. Его Inspector показывает список карт общего каталога. Там можно менять название, тип местности, размер **км × км**, Texture2D превью и SceneAsset. Контроллер уже добавлен в сцену и используется и галереей, и загрузчиком. Каталог отдельно: **DroneLab → UI → Open Maps and Environment Catalog** (`Assets/DroneUI/Resources/DroneLab/ScenarioCatalog.asset`). Другой каталог можно назначить контроллеру.

Каждая запись хранит стабильный id, название, тип местности, размер в **метрах в данных** (Inspector переводит ввод из километров), Texture2D скриншота и SceneAsset (Inspector сохраняет путь сцены). Название находится поверх превью, под изображением — только тип и размеры. Панели подробностей и запуска в галерее нет. Всегда три одинаковые колонки, даже при одной/двух картах или после фильтрации. Поиск и фильтр выровнены по высоте; каретка белая. Картинка не влияет на сцену, физику или погоду.

Скриншоты складывайте в **Assets/DroneUI/Screenshots/Maps** и перетаскивайте в поле Screenshot нужной карты. Рекомендуется PNG/JPG 16:9. Из редактора среды блок превью убран. Рисованных изображений несуществующих карт в каталог не добавлено: начальные записи — реальные Forest и PhysTest, пока с нейтральным placeholder. Размер 0 обозначает «Размер не указан»: заполните реальную площадь, она не угадывается из имени сцены.

Новая карта: подготовить сцену в Unity → добавить запись с уникальным id, сценой, размером и скриншотом → **Добавить карты в сборку** → пересобрать приложение. Кнопка **Добавить сцены из Assets/Scenes** добавляет новые сцены без изменения существующих записей. При первом добавлении автоматически ищет Forest.png / PhysTest.png в папке скриншотов. Добавление внешних игровых сцен на диске клиента пока не реализовано.

## Профили

Стартовые `Assets/DroneUI/Resources/DroneLab/EnvironmentPresets/*.json` и пользовательские профили показаны одинаково. Любой можно редактировать и удалять с подтверждением. Сохранение стартового профиля создаёт переопределение с тем же id; удаление записывает постоянную отметку в `.removed.json`. После перезапуска удалённый профиль не появляется снова; файлы Resources проекта не изменяются. Старые пользовательские GUID и JSON сохраняют совместимость. Перед сменой вкладки/профиля и выходом предлагается сохранить несохранённые изменения.

Пользовательские профили находятся в `Application.persistentDataPath/DroneLab/EnvironmentProfiles`. Импорт/экспорт открывают системный выбор JSON/места сохранения: EditorUtility в Unity Editor, Unicode Win32 диалог на отдельном STA-потоке в Windows, AppleScript Standard Additions в macOS, zenity → kdialog в Linux. Отмена не запускает fallback. При ошибке/отсутствии диалога импорт возвращается к ручному пути, экспорт — к Exchange. Путь и ошибки операции отображаются справа от «Профилей: X». Диалоги standalone здесь не запускались. Поддерживается как обычный JSON физики 1.0.0, так и новый документ:

```json
{
  "documentVersion": 1,
  "id": "<guid>",
  "name": "Боковой ветер",
  "environment": { "schemaVersion": "1.0.0", "...": "полный исходный контракт физики" },
  "visual": { "weatherPresetId": "<asset-guid>", "timeOfDay": 14, "simulateTime": false }
}
```

Это иллюстрация структуры, не готовый physics JSON. Схема физики не изменена. Visual настройки находятся снаружи environment. Сохраняются все поля окружения, включая неактивные дополнительные параметры. Профиль проходит оригинальные ContractValidator/ProfileLoader; совместимость с фактическим дроном дополнительно проверяется перед его первым Initialize.

Редактор содержит **все поля EnvironmentProfile**: gravityMps2, airDensityMode, airDensityKgM3, temperatureK, pressurePa, altitudeM; все шесть windMode, полный windVelocityWorldMps X/Y/Z, gustEnabled, gustIntensityMps, gustTimeScaleS, turbulenceSeed; weather.precipitation/intensityMmPerHour/model; все семь параметров Dryden, включая тройки RMS, масштабов и оси. schemaVersion/model осадков фиксированы контрактом и сохраняются в файле; техническая подпись из интерфейса убрана.

Основные поля — погода, время, осадки, режим/горизонтальная скорость/направление ветра, температура, модель воздуха. Остальное — «Расширенные параметры». °C переводится в K; давление остаётся в Па, высота в м. «Направление ветра» означает «откуда дует» и связано с мировыми +Z (север) и +X (восток), вектор не теряет вертикальную компоненту. Для CustomField источником является Enviro или назначенный провайдер, поэтому ручная скорость/направление недоступны.

Значения стандартных физических defaults показаны серым и остаются редактируемыми. У каждого параметра есть `?` с назначением, стандартным значением и допустимым диапазоном; физические единицы и смысл уровня моря объясняются там. Численные ошибки и связанные ограничения подсвечивают поля красной обводкой, сохранение/экспорт не проходят до исправления. Ограничения UI дополнительно ограничивают атмосферу/скорость/гравитацию рабочими диапазонами; исходная схема физики не переписана.

Визуальные defaults берутся из выбранной основы Enviro. При ручном изменении этих полей «Погода» отображает **Кастомный**, сохраняя `weatherPresetId` и стандартные значения в вопросах. Ввод исходного значения убирает переопределение; выбор основы (включая повторный выбор текущей) сбрасывает все визуальные overrides. Кнопки «Из пресета» удалены. При «Из сцены» числа в редакторе справочные: реальное наследование происходит при запуске выбранной карты.

Статус редактора: пусто после открытия без редактирования, «Изменения не сохранены» при правках, «Сохранено» после успешного сохранения. Кнопки «Отменить» нет; защита от потери изменений при переходах сохранена. Общий dropdown теперь собственный компактный компонент: 16 px текст, 34 px строки, графитовый popup внутри той же масштабируемой страницы, прокрутка, стрелки клавиатуры и Escape.

## Enviro и физическая модель

Каталог регистрирует реальные EnviroWeatherType по стабильному AssetDatabase GUID, не по индексу. При первом открытии Unity пустой список заполняется установленными пресетами; дальше **Зарегистрировать основы погоды Enviro** только добавляет новые. В UI одинаковые основы объединяются, названия русские; при регистрации сначала предпочитаются отдельно настроенные Forest assets. Старые id остаются доступными загрузчику. Rain/Snow/Hail не предлагаются в «Погода»: эта настройка задаёт небо/освещение/облака/туман, осадки задаются отдельно. Названия и превью можно изменить в Inspector, id сохранять.

В профиле можно переопределить визуальную турбулентность растительности, мокроту/снег поверхности, coverage/density облаков; при ENVIRO_HDRP — fog attenuation distance, baseHeight и maxHeight. Драйвер клонирует выбранный погодный preset, не изменяет Enviro assets или настройки Forest на диске. Time module необходим для времени суток, Fog/Clouds/Effects modules — для соответствующих эффектов.

Физическая среда сохраняет приоритет. Constant/Gust/Turbulence/DrydenFrozen используют существующий RuntimeEnvironment без новых сил и без двойного ветра. В Enviro и WindZone передаётся горизонтальная часть того же поля, включая порывы. Вертикальный ветер остаётся физическим: горизонтальная Enviro WindZone его не отображает. Визуальная скорость нормируется через fullStrengthWindMps и насыщается при 1, физический ветер не обрезается. windTurbulence Enviro не заменяет физическую турбулентность/Dryden.

Для CustomField используется существующий EnviroWeatherController/IWindProvider. Источник воздуха для запуска из профиля — именно JSON физики: это сохраняет Constant density и корректный смысл sea-level temperature/pressure в StandardAtmosphere. Нельзя незаметно заменить их LOCAL live-air колонкой Enviro. Драйвер преобразует заданные sea-level значения в локальные для визуального адаптера. В этом режиме редактор не предлагает независимый переключатель live-air; ранее настроенное поведение при прямом открытии сцены сохраняется.

Осадки сохраняют VisualOnly metadata. Из модуля Effects выбранной сцены берутся доступные эффекты дождя/снега/града, даже если их нет в выбранной основе неба. Для типовых Rain/Snow/Hail (также русских имён) emission = clamp(intensityMmPerHour / 20, 0, 1): это **явная демонстрационная шкала**, не калибровка частиц в мм/ч. Для иных имён можно задать rainEffectName/snowEffectName/hailEffectName в каталоге; для града нужен отдельный реальный prefab/effect в модуле Effects. При отсутствии нужного эффекта выводится предупреждение, другой тип частиц не подменяется. Мокрота и снежный покров — независимые визуальные цели, сами осадки не перезаписывают их. Вода/лёд не добавляют силы или массу аппарату.

## Запуск

В «Новой симуляции» карта и профиль выбираются независимо. `DroneScenarioLaunch.Load(map, document, catalog)` загружает полный путь сцены. Новый опциональный PreparingSceneBody hook адаптера исполняется после назначения стандартных TextAsset и до первого Initialize. Он назначает валидированный environment JSON без повторной инициализации летящего дрона. После sceneLoaded отдельный визуальный драйвер ждёт первый валидный Enviro frame и применяет погодную копию/время. Сценарий не хранится в карте, настройки профиля не меняются при просмотре галереи.

Профили переменной атмосферы требуют совместимых CtCq/PerformanceMap роторов. Запуск через Enviro дополнительно проверяет локальную температуру 200–330 К, давление 1000–200000 Па и высоту −500–11000 м. Несовместимые параметры отклоняются с сообщением. Перед стартом сцена должна уже содержать настроенный дрон; каталог не импортирует/не создаёт модель дрона автоматически.

## Проверка в Unity

1. После импорта открыть MainMenu; проверить масштабирование, оба раздела, dropdown без синего выделения, прокрутку и Escape.
2. Назначить скриншоты и размеры Forest/PhysTest в каталоге; проверить поиск/фильтр.
3. Изменить стартовый профиль «Порывы ветра» и сохранить без создания копии; перезапустить. Удалить другой стартовый профиль, перезапустить и убедиться, что он не вернулся. Проверить три статуса, красные поля, все подсказки, системный импорт/экспорт и ручной fallback.
4. Запустить совместимую карту/дрон через «Новую симуляцию». Сверить ActiveEnvironmentJson и WindVelocityWorld, порывы WindZone, время, облака/туман. Для CustomField сверить провайдер до Initialize.
5. В Test Runner выполнить DroneLab.UI.Tests; проверить отказ несовместимого measured профиля и импорт некорректных данных.

Unity Editor/Play Mode здесь не запускались. Полноценная визуальная проверка совпадения с референсом и сторонних Enviro modules требует Unity.

## Аудит покрытия EnvironmentProfile → UI → Enviro

Все **21 изменяемое поле** контракта 1.0.0 доступны; векторы считаются одним полем. Ни один параметр не убран ради упрощения UI. `schemaVersion` и `weather.model=VisualOnly` — две фиксированные константы, не настройки. Все поля передаются в JSON, даже если выбранная модель их не использует.

| Группа полей | Физическое применение | Визуальный Enviro |
|---|---|---|
| gravityMps2 | Вес и динамика Rigidbody | Прямого аналога нет |
| airDensityMode, airDensityKgM3 | Постоянная/вычисляемая плотность для сопротивления и совместимой тяги | Плотность не задаёт туман/облака |
| temperatureK, pressurePa, altitudeM | Воздух, атмосферная колонка, температура для включённых тепловых моделей | Локальная температура и опорные данные адаптера; давления/высоты нет как отдельного визуального эффекта |
| windMode, windVelocityWorldMps | Источник и средний физический вектор | Горизонтальный вектор → Environment/WindZone; вертикальная компонента остаётся физической |
| gustEnabled, gustIntensityMps, gustTimeScaleS | Периодические усиления и/или параметры простой турбулентности | Передаётся результат того же поля у текущего дрона; отдельная сила не добавляется |
| turbulenceSeed | Повторяемое поле простой/спектральной турбулентности | Не отдельный визуальный seed, а тот же рассчитанный ветер |
| Все 7 dryden.* | Спектральное замороженное поле Драйдена; только соответствующая модель | Результат поля → горизонтальный визуальный ветер |
| weather.precipitation, intensityMmPerHour | VisualOnly metadata; нет сил от воды/льда | Доступные эффекты сцены с демонстрационной шкалой интенсивности |

Дополнительные `visual.*` поля — время/ход времени, турбулентность растительности, мокрота, снежный покров, покрытие/плотность облаков и 3 HDRP-поля тумана — все подключены к соответствующим модулям Enviro. Их назначение «Только визуал» указано в подсказках; звёздочки из подписей убраны. Не вся библиотека параметров Enviro вынесена в UI: настройка лучей/экспозиции/качества/отдельных типов облаков, аудио, молний, календаря и скорости суток остаётся в модулях сцены.

Модель ветра — выбор способа получения физического потока, а не визуального пресета. Модель Драйдена — спектральная турбулентность с независимыми продольной/поперечной/вертикальной компонентами и воспроизводимым переносом. Реализация не превращается в полную CFD или погодную модель. Реакция конкретного дрона зависит также от его physicsConfiguration, drag/rotor/thermal параметров и совместимости профиля тяги, которые настраиваются в профиле **дрона**, а не окружения.

Подготовлены дополнительные EditMode проверки хранения переопределений/удалений, собственных границ полей, осадков, наследованной границы тумана и удаления дублей погоды. Требуют Unity Test Runner; здесь не выполнялись.


## Уточнения редактора и стартовые условия

Новый профиль сразу находится в состоянии «Изменения не сохранены» и доступен для сохранения. Открытый существующий профиль не показывает статус/кнопку сохранения до изменения. Название и числовые поля фиксируют значение по Enter или потере фокуса; черновой ввод проверяется отдельно, не открывая кнопку сохранения сам по себе. Возврат к исходным значениям скрывает кнопку. После сохранения остаётся «Сохранено». Уведомление об операции и путь исчезают через 10 секунд после последнего сообщения.

В редакторе нет обязательных звёздочек. Название должно содержать 1–100 символов; остальные обязательные поля физического документа заполнены стандартными значениями. Дополнительные visual.* наследуют выбранную погодную основу, пока не переопределены. Ограничения и сочетания проверяются перед сохранением: например, осадки требуют положительной интенсивности, а Драйден — единичной горизонтальной оси переноса. Название производителя погодной системы в пользовательских текстах не показывается.

Библиотека больше не перебирает тестовые environment_* физического модуля. Три отдельных редактируемых/удаляемых профиля имеют новые стабильные id; старые отметки удаления не скрывают их, а удаление этих новых профилей сохраняется как прежде. Ранее сохранённые пользовательские документы остаются доступными. Это разумные учебные условия для сравнения поведения дрона, а не измеренная погода конкретного полигона или высоты.

| Профиль | Средний поток | Возмущения | Визуальная основа |
| --- | --- | --- | --- |
| Ясный день · первые полёты | 0 м/с | выключены | ясно, 14:00 |
| Северо-западный ветер · порывы | 5 м/с от 315° | плавные усиления до 8 м/с, цикл 12 с | небольшая облачность, 13:00 |
| Западный ветер · турбулентность | 4 м/с от 270° | Драйден: RMS 1 / 0,7 / 0,4 м/с; масштабы 60 / 25 / 15 м; перенос на восток 4 м/с | переменная облачность, 16:00 |

Во всех трёх: 15 °C, 101325 Па, высота отсчёта 0 м, постоянная плотность 1,225 кг/м³, g=9,81 м/с². Постоянная плотность позволяет использовать и коэффициентные, и измеренные роторные модели. Падающие осадки выключены; визуальные свойства материалов/облаков наследуются от основы. Профиль Драйдена не включает дополнительные периодические порывы.

### Что именно задаёт ветер

Скорость и направление — удобная запись горизонтального среднего вектора X/Z. Они синхронизируются, не складываются. X — восток, Y — вверх, Z — север; Y задаёт отдельную вертикальную компоненту того же среднего потока. Направление в градусах обозначает источник: откуда дует. Средний западный ветер 4 м/с — [4, 0, 0].

Порывы — повторяющиеся плавные усиления вдоль среднего потока: добавка = amplitude × (1 − cos(2πt/period)) / 2. Средние 5 м/с + амплитуда 3 м/с = 5–8 м/с. Простая турбулентность — пространственное трёхмерное поле из восьми гармоник; её сила задаётся gustIntensityMps, размер структур связан с gustTimeScaleS и скоростью среднего переноса. Драйден — альтернативное спектральное поле: отдельные RMS, масштабы трёх компонент и скорость переноса. RMS описывает среднеквадратичный разброс, а не максимальное отклонение. Обе модели воспроизводятся по seed.

Выбор windMode взаимоисключающий: простая турбулентность и Драйден одновременно не работают. Средний поток добавляется к выбранной модели возмущений. gustEnabled может отдельно накладывать периодические усиления на Constant/Turbulence/DrydenFrozen; в Gust включён обязательно, в None/CustomField выключен. При одновременной простой турбулентности и периодических порывах параметры amplitude/timeScale используются обоими механизмами; в Драйдене собственные колебания задают sigma/lengthScale. Это существующее поведение физики, формулы не менялись.

Драйвер берёт итоговый физический поток в позиции дрона и передаёт горизонтальную часть погодному контроллеру и WindZone. Погодная скорость = clamp(|windXZ| / fullStrengthWindMps, 0, 1); стандартный fullStrengthWindMps = 20 м/с. Например, 5 м/с → 0,25, максимум порыва 8 м/с → 0,4. Физическая скорость сохраняется в м/с. При CustomField источником служит провайдер сцены; драйвер исключает обратное самоуправление того же погодного адаптера.

Проверка этой правки вне Unity: 21 Python-тест прошёл; UPM physics/demo/environment совпадают с исходниками; все три стартовых JSON прошли исходную JSON Schema 2020-12, ссылки погодного каталога и проверки согласованности воздуха/ветра; 22 C# файла UI разобраны без синтаксических ошибок. Добавлены пять EditMode случаев для совместимости стартовых профилей, цикла порывов и повторяемости Драйдена; они здесь не запускались. ### Отмена и сохранение положения редактора

«Отменить» появляется при изменениях/ошибочном вводе и восстанавливает открытый профиль без записи на диск. Отмена нового профиля удаляет черновик и открывает первый сохранённый профиль; при пустой библиотеке остаётся предложение создать/импортировать профиль. Сохранение и перестроение формы сохраняют раскрытие расширенных параметров, блока Драйдена и позицию прокрутки. Подсказка скорости находится после числового поля, направления — после компаса.

Подпись погодного dropdown имеет собственное ChangeEvent<string>: раньше его всплытие запускало повторный выбор основы, очищало visual.* и пересоздавало форму. Теперь событие подписи останавливается на Label, а обработчики выбора принимают только события самого dropdown. Изменение визуального параметра показывает «Кастомное», сохраняя id основы и переопределение.

Для этой правки повторно прошли 21 Python-тест и разбор синтаксиса 22 C# файлов. Подготовлены две Editor-регрессии: изменение подписи не выбирает погодную основу; правка облачности сохраняет переопределение/раскрытый блок, а отмена восстанавливает исходный профиль. Эти Editor-тесты, компиляция и визуальное отображение здесь не запускались.

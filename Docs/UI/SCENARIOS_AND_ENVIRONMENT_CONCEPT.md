# «Сценарии и окружение»: предлагаемая концепция

Это проект интерфейса и архитектуры следующего этапа, а не готовая вкладка. Основание — требования выбора местности/погоды и загрузки параметров среды из ТЗ, а также текущие `EnviroWeatherController`, `WeatherSnapshot` и README адаптера среды. Физический контракт не изменяется.

## Что находится на экране

Слева около 60–65% ширины занимает каталог карт: карточки с превью, названием, типом местности и размером игровой области. Выбранная карточка выделена белой рамкой. Над списком — поиск и фильтр местности. Карта выбирается кликом без немедленной загрузки тяжёлой сцены.

Справа — профиль среды: выпадающий список сохранённых профилей, «Создать», «Сохранить копию», «Удалить» для пользовательских профилей. Ниже — короткое описание и редактируемые основные условия. Нажатие «Создать» открывает редактор в этой же панели. Расширенные атмосферные параметры раскрываются отдельно.

Внизу — «Назад» и «Использовать». Последняя сохраняет выбор карты и профиля в подготовке испытания и возвращает в меню. «Новая симуляция» загружает выбранную карту с выбранным дроном и условиями. Статус в нижней строке показывает итоговый выбор. Нет двух конкурирующих кнопок запуска на разных вкладках.

Название «Сценарии» далее обозначает сохранённую комбинацию карты, профиля среды и стартовой позиции, а не ещё одну дублирующую систему настроек. Автоматические программы испытаний с временной шкалой — следующий отдельный этап.

## Как добавлять карты

Для хакатона: встроенные карты, подготовленные через Unity. Нужны 2–3 содержательные карты, а не runtime-редактор или универсальный импорт сцены.

Предлагается `MapDefinition : ScriptableObject` и каталог `MapCatalog`. Поля карты: стабильный `id`, русское название, описание, категория, preview, ссылка на сцену в Editor и проверяемый путь сцены для сборки, площадь/габариты области, стартовые позиции, направление севера, географическая опорная высота, совместимые типы техники. Пользователь видит превью и описание; инженерные привязки остаются в данных карты.

Работа разработчика: импортировать окружение → настроить Terrain/Collider/HDRP → определить старт и север → создать MapDefinition с превью → добавить в каталог → включить сцену в сборку → пересобрать приложение. Editor-валидатор каталога в дальнейшем проверяет уникальные id, превью, существование сцен, запуск и наличие точки старта. На диске клиента нельзя просто подложить произвольный `.unity` или FBX и получить готовую карту симулятора.

Вне сборки карты возможны как подготовленные AssetBundle/Addressables-пакеты с manifest, превью и зависимостями. Они всё равно собираются в Unity под конкретную платформу; совместимость Unity/HDRP и используемые компоненты должны соответствовать приложению. Сначала потребуется контракт пакета карты и загрузчик. Откладываем это до появления реальной потребности в пользовательских картах.

## Карта, среда и сценарий хранятся независимо

- Карта описывает местность, север, опорную высоту и стартовые позиции.
- Профиль среды описывает воспроизводимые погодные/атмосферные условия и выбранный визуальный preset.
- Сценарий ссылается на `mapId`, `environmentProfileId`, стартовую позицию и при необходимости `droneProfileId`.

Один профиль среды можно применить к разным картам. Внешние пользовательские профили среды сохраняются в JSON в `Application.persistentDataPath`; встроенные пресеты неизменяемы, изменения сохраняются копией. JSON можно импортировать и экспортировать без Unity. Это предложение хранения для следующего этапа, не уже реализованная функция.

Новый UI-дескриптор не должен молча менять схему существующего environment JSON физики. Он содержит версию, id, название, ссылку на существующий физический профиль и параметры визуального управления. В runtime он преобразуется в команды имеющегося адаптера. Enviro-пресет выбирается по стабильному зарегистрированному id, не по индексу массива и не по отображаемому названию.

## Редактор профиля среды

| Настройка | GUI | Подключение / состояние сейчас |
|---|---|---|
| Название профиля | Текстовое поле | Новый пользовательский дескриптор |
| Погодный preset | Список доступных сцене пресетов с мини-превью | Зарегистрированный id → `SelectWeather(index, instant)` после готовности адаптера |
| Время суток | Ползунок + часы/минуты | `SetTimeOfDay`; нужен активный Time module |
| Ход времени | «Включено / Выключено» | `SetTimeOfDay(hours, simulate)` |
| Ветер: из пресета / вручную | Выпадающий список | `UsePresetWind` / `SetManualWind` |
| Скорость ветра, м/с | Ползунок + число | 0…`fullStrengthWindMps`; нельзя молча обрезать значения выше шкалы |
| Ветер ОТКУДА дует | Компас + угол в градусах | 0° — с севера, 90° — с востока; север задаёт карта |
| Температура: из пресета / вручную | Выпадающий список + °C | `UsePresetTemperature` / `SetManualTemperature`; влияет на воздух при live-air |
| Местное давление на опорной высоте, гПа | Число в расширенных настройках | Преобразуется в Па для `SetAirReference`; это не давление на уровне моря |
| Опорная высота, м над уровнем моря | По умолчанию из карты, с пояснением | Географическая высота отличается от координаты Unity Y |
| Тип/интенсивность осадков | Метка выбранного пресета; расширенная привязка отдельно | Enviro VFX + `weatherBindings`; сейчас VisualOnly metadata, без сил/обледенения |
| Плавность смены погоды | «Мгновенно / Плавно» | Уже поддерживается аргументом `instant` в `SelectWeather` |
| Физические порывы / турбулентность | Отложенный раздел с явным статусом | Enviro windTurbulence не преобразуется в физический Dryden; нужен отдельный согласованный адаптер |

Основной экран не перегружается всеми параметрами атмосферы. Вывести ветер, температуру, время суток и погодный preset; давление и высоту раскрывать в «Расширенные». Плотность воздуха показывать как рассчитанный результат, а не ещё одно независимое поле, способное противоречить температуре и давлению.

Примеры профилей: «Штиль / день», «Боковой ветер 5 м/с», «Дождь / вечер», «Холодный воздух». Эффект осадков в текущей модели остаётся визуальным — его нельзя выдавать за влияние дождевых капель на динамику дрона. Названия карт в референсе также примеры, не существующий каталог проекта.

## Запуск и живое изменение

Предлагаемый координатор запуска читает сохранённый выбор, загружает карту, получает её север и опорную высоту, проверяет доступность Enviro-пресета и физического профиля. Wind/air providers и параметры JSON связываются до Awake/Initialize дрона. После инициализации Enviro и готовности адаптера выбирается preset, устанавливаются время и переопределения. Управление полётом разрешается только после получения целого валидного снимка среды. Точный порядок должен пройти Play Mode проверки; текущий PhysTest пока содержит заранее настроенные объекты в сцене.

GUI вызывает `EnviroWeatherController`, а не независимо пишет ветер в Enviro и в `DronePhysicsBody`. Snapshot остаётся общей точкой чтения для физики/GUI/записи; отображаем «Задано» и «Применено», чтобы плавный переход не выглядел как ошибка.

Температура/давление влияют на тягу и drag при `syncAir` и совместимых CtCq/PerformanceMap-профилях. Измеренные OmegaSquared/RpmTable не масштабируются автоматически. Источник воздуха/ветра нельзя менять уже после Initialize произвольным переключателем. Выбор `syncAir` фиксируется при подготовке испытания; для его изменения нужна перезагрузка испытания.

В будущем F3 использует тот же редактор для живого изменения погоды. Применение не сбрасывает SOC, температуру моторов, обороты и положение дрона. Новые параметры физической турбулентности вводятся только после разработки общего провайдера, чтобы не получить двойное приложение ветра/порывов.

## Предлагаемый первый этап реализации

1. Каталог встроенных карт и выбор карты с превью.
2. Встроенные профили среды, создание/сохранение пользовательской копии JSON.
3. Связь выбора с подготовкой «Новой симуляции» и текущим адаптером Enviro.
4. После проверки — живой редактор F3 и воспроизводимые сценарии испытаний.

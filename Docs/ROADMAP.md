# Дальнейшее развитие

[Документация](README.md) · [Реализованные возможности](FEATURES.md)

Цель развития — лаборатория для подготовки сценариев, получения качественных датасетов и сопоставления симуляции с реальными испытаниями. Ниже перечислены будущие направления; они не входят в заявленный готовый функционал.

## CFD и датасеты

Следующий уровень — получать аэродинамические характеристики из CFD и измерений, а затем использовать их в вычислительно доступном runtime. Для этого потребуются подготовка геометрии, сетки и граничных условий, расчёт полей потока и давления, проверка сходимости и сравнение с экспериментом.

Результат расчёта может преобразовываться в RPM/J-карты, коэффициенты сопротивления и другие таблицы, уже совместимые с параметрическим подходом проекта. Вычисление площади mesh остаётся геометрическим этапом и не заменяет CFD.

Для датасетов нужны серии сценариев с фиксированными параметрами, происхождение данных, версии моделей, настройки оборудования, синхронизированные эталонные и измеренные значения. Разделение обучающих и контрольных сценариев и сравнение с полевыми данными позволят оценивать качество набора.

## Более подробная физика

Идентификация Cd, инерции и привода; нестационарный inflow, взаимодействие следов роторов, корректные режимы быстрого спуска, расширенные модели винтов и поверхностей. Каждый эффект требует своих параметров и независимой проверки. Перечень моделей и необходимых данных находится в [PHYSICS_REFERENCE.md](Physics/PHYSICS_REFERENCE.md).

## Кроссплатформенность

Подготовка и проверка Player для Linux и macOS, перенос файловых диалогов и ввода, контроль материалов импортированных моделей и графической производительности. Для менее мощных устройств потребуется отдельное решение по рендерингу и качеству.

Текущая основа — Unity и чистый C#; уже имеющиеся CI-проверки Windows/Ubuntu относятся к ядру и инструментам. Полноценная кроссплатформенность приложения требует проверенных сборок.

## Прикладные задачи

| Направление | Следующие задачи |
|---|---|
| Доставка | Груз, изменение COM, ограничения маршрута, точки забора/сброса, критерии выполнения |
| Полевые испытания | Повторяемые сценарии, импорт измеренных логов, сопоставление траекторий и ошибок |
| Инспекция | Цели съёмки, зоны интереса, оценка покрытия камерой и качества результата |
| Навигационные эксперименты | Оцениватель состояния, sensor fusion, более полная зависимость управления от оборудования |
| Автономность | Обход препятствий, посадка, аварийные стратегии, безопасное возобновление миссии |

Развитие начинается с проверяемой связи между параметрами, наблюдаемым результатом и реальными данными. Текущие CSV и переносимые профили дают основу для такого процесса.

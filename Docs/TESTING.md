# Тестирование и проверка проекта

[Документация](README.md) · [Численная валидация физики](Physics/VALIDATION.md)

## Что проверяется

| Уровень | Проверки | Что они подтверждают |
|---|---|---|
| Чистый C# | Физика, среда, дискретные датчики, данные конфигуратора | Логику и численные результаты без запуска Unity-сцены |
| Python | Анализ CSV, экспорт, структура пакетов и связанные регрессии | Форматы и воспроизводимость инструментов |
| Генераторы | DTO, схемы, реестр полей, подсказки | Соответствие исходному контракту |
| Экспорт | UPM, GUID, SHA-256 и ссылки документации | Согласованность опубликованных пакетов с исходниками |
| Unity EditMode / PlayMode | Адаптеры, ввод, сцена, Rigidbody и UI | Интеграцию в движке при фактическом запуске тестов |
| Player | Запуск, материалы, файлы, камеры и экспорт | Работу собранного приложения на целевой платформе |

В ранее зафиксированном прогоне прошли **562 случая ядра/датчиков/навигации** через Roslyn/NUnitLite и **25 Python-тестов**. Это не суммарное число всех тестов репозитория: отдельные проекты среды и конфигуратора имеют собственные наборы. Число обнаруженных тестов текущего checkout следует брать из результатов команд ниже.

В CI используется матрица Windows и Ubuntu. Эти проверки не запускают полноценный Unity Player и не доказывают работу графики на двух ОС. Подготовленная командой EXE-сборка и видео демонстрируют отдельный результат, который нужно проверять по конкретному артефакту.

## Команды

Выполняйте из корня проекта с .NET SDK 8 и Python 3.11:

```bash
dotnet test Tests/DotNet/DroneLab.Physics.Tests.csproj --configuration Release
dotnet test Tests/Environment/DroneLab.Environment.Tests.csproj --configuration Release
dotnet test Tests/Sensors/DroneLab.Sensors.Tests.csproj --configuration Release
dotnet test Tests/Configurator/DroneLab.Configurator.Tests.csproj --configuration Release
python -m unittest discover -s Tests/Python -v
python Tools/build_unity_packages.py --check
python Tools/build_environment_package.py --check
```

Проверка производных файлов контракта:

```bash
python Tools/generate_physics_contract.py
python Tools/generate_configurator_catalog.py
git diff --exit-code -- Assets/DronePhysics/Core/Profiles.Generated.cs Assets/DronePhysics/Resources/DronePhysics/drone-profile.schema.json Assets/DronePhysics/Resources/DronePhysics/environment-profile.schema.json Docs/Physics/PARAMETERS.md Assets/DroneUI/Resources/DroneLab/DroneParameters.json Assets/DroneUI/Resources/DroneLab/DroneParameterDefaults.json
```

Если контракт изменён намеренно, diff сначала нужно проверить и сохранить вместе с исходным генератором. При сообщении об устаревшем экспорте пересоздайте пакеты по [DEVELOPMENT.md](DEVELOPMENT.md).

## Проверка в Unity

Откройте Test Runner через **Window → General → Test Runner**. Запускайте доступные EditMode и PlayMode-наборы в Unity 6000.3.25f1. Записывайте результат только фактически исполненных наборов; разбор C# или сборка со вспомогательными интерфейсами не равны Play Mode.

## Короткая ручная приёмка

1. MainMenu: открыть каталоги, создать копию дрона, сохранить и повторно открыть её.
2. Конфигуратор: импортировать GLB и glTF с внешними ресурсами, проверить материалы, масштаб, привязки винтов, автоматический силуэт, экспорт и обратный импорт комплекта.
3. Запуск: выбрать аппарат и доступную сцену, проверить положение на площадке, включить моторы, взлететь и удерживать высоту.
4. Полёт: проверить F1–F5, FPV, переназначение клавиш, паузу и возврат после потери фокуса окна.
5. F3/F4: при открытии панели проверить WASD/Space; щёлкнуть поле, ввести число, нажать Esc или свободное место и убедиться, что управление вернулось.
6. Оборудование: убедиться в идеальных настройках нового полёта, включить шум и задержку, отключить GPS, проверить прекращение навигации и отсутствие автоматического возобновления.
7. Маршрут: поставить точки, выполнить миссию, остановить её и проверить удержание после прибытия.
8. Запись: сохранить CSV, проверить наличие физических и сенсорных данных, метаданных и события; запустить анализатор.

Перед сдачей повторите этот маршрут в готовом Player. Особое внимание — внешним моделям, файловым диалогам, разрешению окна и правам записи. Численные контрольные наборы и их границы рассмотрены отдельно в [VALIDATION.md](Physics/VALIDATION.md).

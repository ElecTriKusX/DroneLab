# Запись полёта, графики и анализ

[Документация](README.md) · [Датчики](SENSORS.md)

## Записать испытание

1. В F4 выберите запись и задайте интервал строк.
2. Начните запись, выполните нужный эксперимент и остановите её.
3. Откройте папку результатов из панели. Уведомление о сохранённом пути скрывается автоматически через семь секунд.

Интервал задаётся в секундах **времени симуляции**, диапазон **0,02…10 с**, начальное значение **0,1 с**. Частота датчика определяет захват измерений отдельно от записи и ширины графика. Пауза не создаёт новые физические отсчёты.

Результаты находятся в `Application.persistentDataPath/DroneLab/Flights/`, в отдельной папке для каждой записи. Это путь Unity, зависящий от ОС и настроек приложения; кнопка открытия папки надёжнее заранее заданного абсолютного адреса.

## Состав записи

| Файл | Содержание |
|---|---|
| `flight.csv` | Время и сегмент, движение, управление, роторы, силы, питание, температура, энергия и диагностические признаки |
| `sensors.csv` | Канал и номер измерения, захват/доставка, валидность, эталон и измеренные компоненты |
| `drone_profile.json` | Использованный физический профиль аппарата |
| `environment_profile.json` | Исходный профиль среды |
| `sensors_start.json` | Начальные настройки оборудования, геопривязка и параметры записи |
| `sensors_end.json` | Настройки оборудования к завершению |
| `events.txt` | Сохранённые события с временем симуляции |

Формат физического CSV — **1.4.0**. Точные имена колонок задаёт заголовок соответствующего файла. Если часы полёта сброшены, новая часть получает отдельный сегмент; не объединяйте её с предыдущей как непрерывное время.

### Сенсорный CSV

```csv
segment,sensor,sequence,capture_s,delivery_s,valid,truth_x,truth_y,truth_z,measured_x,measured_y,measured_z
```

`segment` выделяет участок часов, `sensor` — канал, `sequence` — номер измерения; времена указаны в секундах. `valid` определяет пригодность значения. `truth_*` и `measured_*` — компоненты эталона и измерения в единицах данного канала. Для GPS это East/Up/North в метрах, для акселерометра — м/с², гироскопа — °/с, магнитометра — мкТл, барометра — давление в Па, дальномера — метры по лучу. График барометра в UI пересчитывает давление в высоту.

Растровые изображения камеры не сохраняются этим CSV как видеопоток. Запись содержит численные сведения и параметры оборудования; получение отдельного набора кадров требует дополнительного экспорта.

Профиль среды является исходным снимком. Изменённое в полёте состояние нужно сопоставлять с телеметрией и событиями, а настройки датчиков между началом и концом — с их снимками. Список событий ограничен, поэтому комплект не следует трактовать как бесконечный подробный журнал всех действий.

Остановка, выход из полёта и завершение приложения закрывают запись. Ошибки доступа к файлам показываются в событиях. CSV — данные испытания; автоматическое воспроизведение полного полёта по ним не реализовано.

## Графики F4

История хранит до 60 секунд. Окна 5/10/20/60 секунд меняют видимый интервал; частота оборудования и CSV остаются отдельными настройками. Измерение показывается сплошной линией, соответствующий эталон — пунктиром. Можно скрывать компоненты и смотреть ошибку.

Векторные компоненты используют цвета X — голубой, Y — оранжевый, Z — зелёный. Для GPS это East/Up/North. Эталон относится ко времени захвата измерения. Низкая частота, задержка и недоступность канала должны учитываться при интерпретации пропусков.

## Анализатор Python

Нужен Python; скрипт использует стандартную библиотеку. Из корня проекта:

```bash
python Tools/analyze_flight.py /path/to/flight.csv
python Tools/analyze_flight.py /path/to/flight.csv --from-s 5 --to-s 15
python Tools/analyze_flight.py /path/to/flight.csv --from-s 5 --to-s 15 > summary.json
```

Замените путь на свой. Если он содержит пробелы, заключите его в кавычки. Скрипт читает **физический `flight.csv`**, группирует сегменты и печатает JSON-сводку. Временной фильтр применяется к времени внутри каждого сегмента. Пустой интервал или ошибочный файл завершаются понятной ошибкой.

Сводка включает доступные статистики физических величин и энергетических проверок. Скрипт не строит автоматически презентацию, PDF или сенсорные графики. `sensors.csv` пригоден для отдельного анализа в Python или таблицах.

## Как сравнивать испытания

Сохраняйте аппарат, среду, включённые модули, seed, шаг физики, оборудование и интервалы. Для проверки шума сравнивайте измерение с эталоном той же отметки захвата. Для сравнения управления используйте одинаковые начальные условия и различайте идеальный GPS от шумного.

Не выводите точность реального полёта из одной красивой траектории. Контрольные данные и область подтверждения физических моделей: [VALIDATION.md](Physics/VALIDATION.md). Дальнейшая работа с датасетами: [ROADMAP.md](ROADMAP.md).

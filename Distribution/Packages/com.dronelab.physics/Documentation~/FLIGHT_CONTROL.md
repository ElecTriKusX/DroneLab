# Этап 2: управление

Физический JSON-контракт 1.0.0 не изменён. Регуляторы не добавляют искусственные силы:
команда проходит через allocator, target RPM, задержку двигателя и реальные силы/моменты
из принятой модели. Существующий компонент DroneTestPilot и его GUID сохранены;
пересобирать сцену не требуется. Новые настройки получают значения по умолчанию.

## Получить и проверить

1. Обновить ветку `physics-packages`: `git pull --ff-only`.
2. Открыть существующую сцену, дождаться компиляции. Выбрать корень дрона.
3. В DroneTestPilot оставить **Read Keyboard = true**, **Input Device = Keyboard**.
   Старое имя Read Keyboard теперь включает выбранный источник ввода.
4. Play → клик в Game View → F → Space: подъём. H: удержание высоты.
5. D: наклон вправо; отпустить: Angle выравнивает аппарат. Скорость по X/Z остаётся.
6. E: вращение вправо; отпустить: вращение затормаживается. Курс не удерживается.
7. Z: Acro. A/D и W/S теперь задают угловую скорость. После отпускания вращение
   прекращается, но достигнутый наклон остаётся. Z возвращает Angle и выравнивает аппарат.
8. Выключить H и отпустить Space: target RPM всех моторов сразу нулевой;
   фактические RPM затухают с постоянной времени моторов. Сглаживание режимов не задерживает stop.
9. Window → General → Test Runner → EditMode, затем PlayMode → Run All.

Сцену и модель этот коммит не меняет. Fixed Timestep по-прежнему 0.01 s.
Настройки Gain существующего пульта сохранены и являются коэффициентами P.
В сворачиваемых Rate/Attitude/Altitude/Vertical Velocity Pid находятся I, D,
предел вклада интеграла и постоянная времени фильтра D.

## Режимы

| Режим | Roll/Pitch | Нейтральный стик |
|---|---|---|
| Angle, Auto Level = true | Заданный наклон, до 20° по умолчанию | Выравнивание |
| Acro, Auto Level = false | Заданная угловая скорость, до 100°/s | Торможение вращения, сохранение наклона |
| Altitude Hold, независимый H | Высота + заданная скорость набора/снижения | Удержание высоты, без удержания X/Z |

Yaw задаёт скорость до 70°/s в обоих режимах. Acro содержит rate-стабилизацию.
Это не прямой ручной differential RPM режим. При Altitude Hold и наклоне более
arccos(0.35) ≈ 69.5° контроллер снимает тягу: данный режим не предназначен для перевёрнутого полёта.
Для переворотов использовать Acro с выключенным H и ручной тягой.

## Геймпад

Остановить Play → DroneTestPilot → **Input Device = Gamepad**. Включить Play.
Используется текущий Gamepad Unity Input System; автоматического смешивания с клавиатурой нет.
При смене источника на лету, отключении выбранного устройства или потере фокуса — disarm.
Подключение обратно требует нового arm. Dead zone стиков задаётся Input System.

| Орган управления | Действие |
|---|---|
| Start / Menu / Options | Arm / Disarm |
| Правый стик X/Y | Roll / Pitch; вперёд = нос вперёд |
| Левый стик X | Yaw |
| Левый стик Y | Набор / снижение только при H |
| Правый триггер RT / R2 | Ручная тяга 0–100% максимальной суммарной тяги; при H игнорируется |
| Западная кнопка X / Square | Angle / Acro |
| Южная кнопка A / Cross | Altitude Hold |
| Северная кнопка Y / Triangle | Reset и disarm |

Синтетический профиль имеет T/W=4: ручное зависание при горизонтальном корпусе
соответствует примерно 25% триггера. Это процент тяги: allocator берёт квадратный
корень перед преобразованием в RPM. Клавиатурный Space сохраняет прежние 38% тяги.
Обычный gamepad поддержан; произвольный USB-радиопульт/Joystick требует отдельного адаптера.
Справка API: [Unity Input System Gamepad](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.4/manual/Gamepad.html).

## Закреплённый контракт ввода

Источник: `Assets/DronePhysics/Core/FlightInput.cs`, версия 1.0.0.
Это отдельный C#-контракт для ввода, не дополнение к профилю физики.

| Поле | Диапазон и смысл |
|---|---|
| Roll | −1…1; плюс наклон вправо, rate вокруг локального −Z |
| Pitch | −1…1; плюс нос вперёд, rate вокруг локального +X |
| Yaw | −1…1; плюс поворот вправо, rate вокруг локального +Y |
| Climb | −1…1; плюс набор высоты, при H масштабируется в m/s |
| Throttle | 0…1; доля максимальной суммарной тяги при выключенном H |

NaN/Infinity превращаются в 0, конечные значения ограничиваются диапазоном.
Кнопки представлены отдельно в PilotInputFrame как события, не как физические параметры.
Для сценариев/AI: Read Keyboard=false и `SetFlightInput(new FlightInput(...))`.
Внешний адаптер сам обновляет команду и её актуальность. Старый `SetTestInput` сохранён.

## Регуляторы и ограничения

Каскад Angle: ошибка направления up в локальных координатах → attitude PID → rate target.
Каскад Acro: rate target прямо от стиков. Rate PID → angular acceleration (rad/s²)
→ полный тензор инерции + gyroscopic compensation → torque (N·m).
Высота: height PID → vertical speed target → velocity PID → vertical acceleration;
далее `mass * (gravity + acceleration) / upright` даёт необходимую тягу.

| Контур | P | I | D | Максимальный вклад I | Фильтр D |
|---|---:|---:|---:|---:|---:|
| Rate | 12 | 2 | 0.15 | 3 rad/s² | 0.04 s |
| Attitude | 5 | 0.1 | 0.1 | 0.3 rad/s | 0.04 s |
| Height | 3 | 0.1 | 0 | 0.5 m/s | 0.04 s |
| Vertical speed | 3 | 0.8 | 0.1 | 2 m/s² | 0.04 s |

Единицы P/I/D зависят от пары input/output конкретного контура.
Это стартовые настройки синтетического TestQuad, не калибровка реального аппарата.
D действует на измерение, поэтому скачок команды не создаёт derivative kick.
I ограничен; интеграция, усиливающая насыщение выхода PID, отклоняется.
Насыщение allocator на предыдущем физическом шаге замораживает интеграцию всех контуров.
Это консервативная защита, без покомпонентного back-calculation.
Disarm, reset, нулевая ручная тяга и смена режима очищают интегралы и историю D.

Rate target сглаживается экспоненциально с τ=0.12 s, независимо от timestep.
При смене режима PID сбрасываются, target rate продолжает сглаживаться от прежнего значения.
Collective переходит за 0.3 s по smoothstep; нулевая ручная команда имеет приоритет.
Включение H фиксирует текущую высоту; затормозить уже имеющуюся вертикальную скорость
и восстановить тягу моторы могут только за физически конечное время.

Ограничения: rate acceleration ±40 rad/s² по осям; vertical acceleration ±4 m/s²;
vertical speed target до max(2, Climb Speed) m/s; height target в пределах ±2 m от текущего Y.
Allocator поддерживает только четыре +Y ротора с управляемой геометрией, допускающей
положительную тягу при нулевом моменте. Сначала ограничивает коллективную тягу, затем
масштабирует весь вектор torque до диапазона моторов. При насыщении часть запрошенного
момента недоступна; HUD показывает Saturation и Torque Authority. Роторы с ненулевым
minimum RPM в физическом профиле могут дополнительно ограничивать распределение;
текущие тесты/настройки предназначены для TestQuad с minimum RPM=0.

## Проверки и пределы результатов

47 математических тестовых случаев прошли, включая 16 новых. Production PID проверен
на одноосевой модели с настоящими allocator, thrust/torque coefficients и motor lag.
На 50/100/200 Hz yaw через 5 s составляет 70.497–70.499°/s при цели 70°/s;
остаток — затухающий интегральный переходный процесс. Height step 2 m через 12 s:
1.9998–2.0001 m. Проверены торможение, attitude cascade, постоянный внешний момент,
anti-windup, reset, отсутствие D kick и сохранение collective при насыщении.

12 Unity-тестов физики/пульта/ввода доступны в PlayMode (5 новых).
Здесь Unity отсутствует: импорт, работа Input System и трёхмерное поведение требуют
запуска этих тестов в редакторе и ручной проверки сценой. Не считать этот документ
утверждением о прохождении Unity-тестов.

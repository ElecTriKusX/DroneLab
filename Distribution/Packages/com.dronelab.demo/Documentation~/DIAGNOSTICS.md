# Этап 8: запись полёта и отказ мотора

## Что нажать

1. Выйди из Play. Выдели корень своего дрона.
2. **DroneLab → Diagnostics → Add Flight Recorder and Motor Fault Scenario**.
3. На корне появятся **DroneTelemetryRecorder** и **DroneMotorFaultScenario**.
4. В Recorder оставь **Record On Enable** включённым. В Fault Scenario оставь
   **Automatic Fault** выключенным для первого полёта.
5. Сохрани сцену → Play → **F → H**. Полетай 10–20 секунд, останови Play.
6. **DroneLab → Diagnostics → Open Flight Recordings Folder** открывает результаты.
   В каждой новой папке находятся `flight.csv`, `manifest.json`,
   `drone_profile.json` и `environment_profile.json`.

Начало записи и полный путь выводятся в Console. Папки создаются внутри
`Application.persistentDataPath/DroneLab/Flights`; расположение не зависит от
папки проекта. Старые полёты не перезаписываются. Recorder пишет каждый physics step,
сбрасывает буфер каждые Flush Every Rows строк и закрывает файл при выходе из Play.
В меню компонента **⋮** доступны **Start recording** / **Stop recording**.
Остановка записи сохраняет физику; ошибка файловой системы завершает только запись.

## Проверка отказа

1. Выйди из Play. В **DroneMotorFaultScenario** включи **Automatic Fault**.
2. **Rotor Index = 0**, **Seconds After Arm = 5**, **Remaining Drive = 0**.
3. Play → **F → H**. Через пять секунд после постановки на arm первый привод откажет.
4. Его RPM/тяга затухают по responseTimeDownS; в HUD появляется **MOTOR DRIVE FAULT**.
   Ожидается потеря устойчивости/высоты, а не продолжение обычного висения.
5. В меню компонента доступны **Inject selected motor fault** и
   **Restore all motor drives**. Restore также выключает автоматический сценарий.
   **Backspace** сбрасывает позу, батарею, часы и все неисправности.

Индекс соответствует порядку rotors в JSON: у TestQuad 0=FL, 1=FR, 2=RR, 3=RL.
Для своей геометрии смотри rotorId. Сценарий по умолчанию выключен: установка компонента
сама по себе не создаёт отказ. Автоматический таймер работает в FixedUpdate; в явно
шагаемых стендах применяй SetRotorDriveAuthority вручную перед нужным шагом.

Модель отказа — **потеря команды на привод**: target RPM умножается на Remaining Drive,
далее используется обычный motor lag. При 0 батарея больше не питает этот мотор;
остаточное вращение продолжает давать T/Q и rotor drag до затухания. Энергия такого
выбега не берётся из батареи и не моделируется отдельной механической системой.
При 0.5 целевая скорость вдвое ниже; в модели ω² установившаяся тяга примерно четверть.
Это не заклинивший вал, не разрушенный винт и не изменение Ct/Cq или массы.
Возвращение привода использует обычное время раскрутки.

Quad-пульт не перераспределяет управление для устойчивого трёхмоторного полёта.
При неисправности его PID прекращают накапливать интеграл, но их команды могут быть
невыполнимы. Saturation показывает возможности обычного allocator, отдельный drive_fault
показывает нарушение его предположений. Физика допускает другое число роторов;
этот тестовый пульт по-прежнему предназначен для Quad.

## Смысл CSV

Формат телеметрии имеет собственную версию **1.0.0**; JSON-профили остаются **1.0.0**.
Столбцы и единицы закреплены в Core/FlightTelemetry.cs. Десятичный разделитель — точка,
разделитель столбцов — запятая; неизвестные значения — пустая ячейка, реальный ноль — 0.
Имена rotorId экранируются по CSV. Таблицы можно открыть в Excel через **Данные → Из текста/CSV**.

| Группа | Что записывается |
|---|---|
| segment, time_s, dt_s | Сегмент после reset, время начала шага, фактический dt |
| Поза/движение | World COM в метрах, rotation quaternion x/y/z/w, world linear velocity, body-local angular rate в rad/s |
| Управление | Armed, Angle/Acro, H, saturation, desired body rates, roll/pitch/yaw/climb/throttle |
| Среда/корпус | Плотность, MSL-высота, ветер COM, world body drag/torque |
| Энергетика | SOC, заряд Ah и энергия J на конец шага; напряжение, ток и мощность текущего шага |
| Каждый ротор | Команда RPM fraction, drive authority, фактические RPM, T/Q/J, CSV measured current отдельно от estimated bus current, ground h/gain, rotor-point wind/drag, clamp |
| VFX estimate | induced_hover_mps = sqrt(max(T,0)/(2ρπD²/4)) |

Снимок снимается через **StepPrepared**, после подготовки сил и motor/power state,
**до интегрирования Rigidbody**. Поза/скорость относятся к time_s, силы и новые RPM —
к шагу [time_s, time_s+dt_s], поля с суффиксом `_end` — после расхода батареи за этот шаг.
Это диагностическая дискретизация, а не поток синхронных измерений реальных датчиков.
Ток измеренной CSV-таблицы не становится фактическим током батареи.

Reset начинает следующий segment в том же CSV, время снова с нуля. Повтор Initialize
с другим runtime snapshot завершает старый файл и начинает новую папку. Сохраняются
именно JSON, принятые Initialize, независимо от последующей смены полей Inspector.
Manifest содержит Unity/scene, timestep на старте, rotor order, опорный world Y атмосферы,
настройки пульта и сериализуемого custom wind component. Он не заменяет сцену, Terrain,
геометрию collider или конфигурацию программного IWindProvider. Настройки сохраняются
на старте записи: изменения коэффициентов пульта во время полёта требуют новой записи.

## Анализ и сравнение шага

Установи Python 3.8+ и запусти из папки проекта:

```bash
python Tools/analyze_flight.py "C:/path/to/flight.csv"
python Tools/analyze_flight.py "C:/path/to/flight.csv" --from-s 5 --to-s 15
```

Скрипт без сторонних библиотек выводит JSON по каждому segment: dt, разброс высоты,
RMS вертикальной скорости, среднюю сумму T и вес, число fault/power-limited строк,
SOC/заряд/энергию при наличии и невязку интеграла Pbus dt. Неполные строки, NaN и
переворот времени внутри сегмента отклоняются. Сырые записи и профили не изменяются.
Если начало/конец интервала выбраны посреди записи, невязка энергии учитывает исходный
накопленный счётчик. Средняя сумма T близка mg только для спокойного горизонтального
висения без контакта: при наклоне/опоре/вертикальном drag такое сравнение недостаточно.

Для сравнения 50/100/200 Hz сделай три полёта со **Fixed Timestep = 0.02 / 0.01 / 0.005**,
одинаковыми JSON, стартом, seed и командами. Автоматически менять глобальный timestep
модуль не будет. Ручные команды не повторяются точно; изолированные тесты используют
одинаковые команды и интервалы. Сравни установившийся участок H, fault transition
и энергетический баланс. Совпадение при разных dt не подтверждает реальные коэффициенты.

## Калибровка и интеграция

Для проверки реального профиля нужны независимые измерения массы/COM/инерции,
RPM → T/Q/current, OCV(SOC), сопротивления и drag. Сначала проверяй статическую тягу,
затем энергетический баланс, потом отклик и ветер; фиксируй источник/условия/плотность
через parameterProvenance. Нельзя подобрать Cd по одному кадру или объявить настоящей
калибровкой T, взятую из самой симуляции. Процедура подготовлена, калибровка по реальным
измерениям ещё не выполнена. Реальные параметры профиля по решению пользователя отложены.

`DronePhysicsBody.GetRotorTelemetry(index)` предоставляет readonly struct для визуала:
RPM, силы, ground effect, ветер и оценку потока, без дополнительных сил/запросов среды.
Для вращения пропеллера направление берётся из JSON spinDirection; ReactionSign имеет
противоположный знак. Induced hover estimate не создаёт CFD-поток, не включает VFX Graph,
не учитывает wake/вихри и не меняет аэродинамику. Готов API для интеграции отдельного визуала.

## Какие тесты запускать

**Window → General → Test Runner**, выбрать сборки **DroneLab.Physics.EditModeTests**
и **DroneLab.Physics.PlayModeTests**. Новые DiagnosticsRigidbodyTests проверяют отказ,
выбег/батарею/reset, фазу CSV, закрытие файла/сегменты и 50/100/200 Hz.

WindowsInput_MouseMovements_AreDetected и WindowsInput_RemoteDesktopMouseMovements_AreDetected
принадлежат пакету Unity Input System, а не DroneLab. В [исходниках Input System 1.20.0](https://github.com/Unity-Technologies/InputSystem/blob/1.20.0/Packages/com.unity.inputsystem/Tests/IntegrationTests/IntegrationTests.cs)
оба имеют Ignore("Unstable due to 1252825"): пропуск намеренный, менять пакет не требуется.
Фактические результаты и ограничения запуска закреплены в VALIDATION.md.

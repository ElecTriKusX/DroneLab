# Этап 5: ground effect и сопротивление роторов

Реализованы два независимых optional-модуля: `groundEffect` и `rotorAerodynamics`
(пока означает только rotor drag). Старые JSON с обоими флагами false сохраняют прежнюю
физику. Схема и единицы контракта 1.0.0 не менялись. Исторический статус этапа 5: flapping, induced drag и gyroscopic
rotor effects остаются в плане и отклоняются при включении: формулы и коэффициенты ещё
не приняты. Не включаем их произвольными множителями.

## Ground effect

Для каждого ротора R=D/2, h — расстояние от центра ротора до поверхности по -thrustAxis:

`G = min(maxMultiplier, 1 + coefficient * (R / (4 max(h,minHeightRadiusRatio R)))²)`.

Это **наша ограниченная эмпирическая модель**, а не вычисление реального поля потока.
Она добавлена по ранее принятой спецификации; коэффициент надо идентифицировать.
[Эксперименты NASA](https://ntrs.nasa.gov/citations/20160006428) описывают увеличение
тяги при близости ротора к поверхности, но не подтверждают именно эту формулу и demo-коэффициенты
для нашего FPV-дрона. Из mesh коэффициент не извлекается.

Unity-поиск поверхности:

- Используется PhysicsScene объекта, поэтому локальные тестовые сцены работают отдельно.
- От каждого центра ротора — ray по -axis; Collider/TerrainCollider, слои Ground Layers.
- Triggers, attached Rigidbody дрона и все коллайдеры его иерархии исключаются.
- Среди пригодных hits выбирается ближайший. Не полагаемся на порядок буфера.
- Угол между нормалью поверхности и +axis меньше 60°; при приближении к 60° усиление
  плавно исчезает: alignment fade = clamp((dot(axis,normal)-0.5)/0.5,0,1)².
- Формула сохраняется до 45R; от 45R до 50R усиление плавно умножается на
  `1-smoothstep(45R,50R,h)`. На 50R и дальше G=1. Это предотвращает скачок на границе
  конечного collider query даже при большом пользовательском coefficient.
- Нет подходящего hit → G=1, GroundHeightM=+Infinity, HUD показывает «—».
- Буфер 32 hits переиспользуется, при переполнении растёт до 2048. Если лимит достигнут,
  этот probe пропускается с единичным предупреждением; сузить Ground Layers. Неполный
  набор hits не используется для выбора поверхности.

[Официальный PhysicsScene.Raycast](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/PhysicsScene.Raycast.html)
предоставляет query с заранее выделенным буфером и фильтром triggers. Это недорогой
запрос к collision scene; силуэт mesh не пересчитывается и CFD не запускается.

Сила `T_effective = G*T_free_air` только при T>0. Нулевой/отрицательный T не усиливается.
Q и currentA из исходной performance-модели остаются прежними: отдельная коррекция
нагрузки/тока здесь не определена. Значит этот этап не моделирует изменение электрического
потребления у земли. Motor lag и команды RPM сохраняются.

Модель требует **free-air / out-of-ground-effect исходных данных винта**. Если таблица
измерена уже рядом с полом, включение G повторно посчитает тот же эффект. Loader предупреждает
об этом требовании, но сам не может определить условия измерения из чисел таблицы.

Один луч через центр диска приближает поверхность, не оценивает весь footprint винта.
Края площадок, тонкие опоры, стены, сильные наклоны и динамический outwash не имеют
подтверждённой точности. Минимальная высота и maxMultiplier ограничивают численный эффект,
а не заменяют столкновения: Rigidbody/Collider продолжают обрабатывать контакт отдельно.

## Rotor drag

`VpointAir = Vcom - Vwind + omegaBody × (rRotor-rCOM)`

`Vperp = VpointAir - axis * dot(VpointAir,axis)`

`FrotorDrag = -rotorDragCoefficientKgPerRad * omegaRotor * Vperp`.

Коэффициент имеет единицы kg/rad; omegaRotor в rad/s, скорость m/s, сила N.
Модель линейна по боковой скорости и оборотам. Чистый осевой поток не даёт drag;
при omegaRotor=0 сила равна нулю. Линейный закон применяется в
[официальном PX4 Gazebo motor model](https://github.com/PX4/PX4-SITL_gazebo-classic/blob/main/src/gazebo_motor_model.cpp),
который ссылается на Martin/Salaün 2010. Наш вариант использует скорость **точки ротора**,
поэтому учитывает вращение корпуса. Значения коэффициента PX4 не считаются калибровкой
нашего аппарата; demo = 0.0001 kg/rad нужно позже заменить данными.

Сила прикладывается в точке ротора через AddForceAtPosition, что уже создаёт r×F.
Отдельного повторного AddTorque для drag нет. RotorDragTorque — только сумма для телеметрии.
Относительно воздуха `sum(F·VpointAir) <= 0`, эквивалентно `Fsum·VcomAir + torqueSum·omegaBody <= 0`.
Ветер может ускорить аппарат в world frame: диссипация определена в системе воздуха.

Нет неявного множителя rho, увеличения осевой тяги, rolling moment, BEM или flapping.
K — эмпирический коэффициент для условий идентификации; изменение плотности требует
проверки его применимости. Ct/Cq-карта учитывает осевой поток, rotor drag — поперечный;
добавочный induced/translational-lift множитель поверх карты не введён.

Сопротивление корпуса и сопротивление роторов суммируются как разные силы. Для корректной
калибровки Mesh Silhouette/Surfaces должны описывать неподвижную часть аппарата: исключить
вращающиеся пропеллеры и не задавать отдельные pressure patches для того же rotor drag.
Остановленный винт не получает статическое сопротивление от этой модели; его отдельная
аэродинамика пока не реализована.

Этап 10 отдельно расширяет поток axial inflow/lift/flapping; [ROTOR_FLOW.md](ROTOR_FLOW.md).
Описанный выше старый H-force не меняет формулу или коэффициент.

## JSON и совместимость

```json
"groundEffect": {
  "coefficient": 1.0,
  "minHeightRadiusRatio": 0.25,
  "maxMultiplier": 1.5
}
```

Для каждого ротора, если rotorAerodynamics=true:

```json
"advancedAerodynamics": { "rotorDragCoefficientKgPerRad": 0.0001 }
```

Ground effect object обязателен при groundEffect=true; advancedAerodynamics нужен у всех
роторов при rotorAerodynamics=true. K>=0, minHeightRadiusRatio>0, maxMultiplier>=1.
Все настройки копируются в immutable runtime snapshot. При false соответствующие
сохранённые значения не создают силы. Импорт геометрии и CSV сохраняет эти поля.

MaxTotalThrust/T/W и allocator остаются **номинальными free-air/J=0**. PID компенсирует
ground gain и дополнительные моменты, пока хватает запаса; allocator не знает текущий G
и не обещает точный wrench при разных высотах под роторами. При yaw с rotor drag может
потребоваться постоянная разница RPM: это компенсация тормозящего момента.

## Проверить на своём Terrain

1. Получить physics-packages, дождаться компиляции.
2. Window → General → Test Runner → EditMode → Run All, затем PlayMode → Run All.
3. Выйти из Play; выбрать свой корень с DronePhysicsBody и назначенным текущим JSON.
4. DroneLab → Rotors → Create Profile with Rotor Effects.
5. Оставить Ground effect и Rotor drag включёнными. Для первой проверки demo-значения:
   coefficient=1, min h/radius=0.25, max multiplier=1.5, drag K=0.0001.
6. Validate and save new drone JSON → новое имя `drone_rotor_effects.json`.
   Профиль назначится дрону; сохранить сцену. Геометрия, COM, масса, RPM-таблицы/карты и
   времена моторов сохраняются. Исходный JSON не заменяется.
7. В DronePhysicsBody → Ground Layers оставить Default Raycast Layers либо выбрать слой
   Terrain/площадки. Нужен TerrainCollider. Старые experimental force scripts не включать.
8. Play → F → H; затем Ctrl снижать целевую высоту. HUD покажет ground h и GE каждого ротора.
   У земли G>1; на высоте G→1. Не путать World Y с расстоянием до Terrain.
9. При неизменной высоте близко к поверхности H может удерживать аппарат на меньших RPM.
   Для пропеллера D=0.127 m эффект при h=0.10 m: G≈1.0252 (около 2.5%).
   С метра усиление уже очень мало. Масштаб эффекта зависит от **диаметра JSON**, а не
   внешнего вида винтов. Реальный профиль отложен по решению пользователя.
10. С ветер-профилем или после наклона появится Rotor drag; при установившемся yaw
    тормозящий момент может поддерживать RPM spread. Жёлтые Gizmos — ground probes,
    оранжевые — силы rotor drag. H не удерживает X/Z.

Для отдельного тестового стенда есть три синтетических пресета:
`quad_test_ground_effect.json`, `quad_test_rotor_drag.json`, `quad_test_rotor_effects.json`.
У них TestQuad-геометрия; для своей модели удобнее меню сохранения нового профиля.

Скриншот пользователя 2026-10-05 подтверждает этап 4: Alt hold true, vy≈0, tilt≈0,
суммарная тяга≈9.81 N для 1 kg, yaw≈0, Saturation false. Горизонтальная скорость≈0.49 m/s
допустима без position hold; неодинаковые RPM компенсируют геометрию/COM и Q(T) таблицы.
Ток в HUD пока табличный, а не расчёт работающей батареи.
